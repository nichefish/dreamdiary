## 1. 목표와 범위 (1단계)

모바일 1단계(v0.1)의 목표는 로그인 사용자가 자신의 저널 기록을 날짜 또는 검색 조건으로 찾아 읽는 **조회 전용 리더**다. 1단계에서는 쓰기 기능을 만들지 않는다.

### 1.1 성공 기준

**읽기가 완벽하게 동작하고, 웹과 같은 복사·내보내기를 제공하는 것**을 1단계 성공으로 본다.

1. 선택한 일·주·월의 기록을 조회할 수 있다.
2. 키워드 또는 태그로 기록을 찾을 수 있다.
3. 조회·검색 결과에서 기록의 상세 본문과 태그·소속 스레드를 읽을 수 있다.
4. 그 기간의 태그와 스레드를 기록과 같은 화면에서 볼 수 있다.
5. 웹과 같이 기록을 복사하고 텍스트로 내보낼 수 있다.
6. 저널 데이터의 생성·수정·삭제 없이 위 흐름을 완료할 수 있다.

### 1.2 범위 밖 (1단계)

다음 쓰기 기능은 1단계 범위에서 **명시적으로 제외**한다.

- 엔트리·일자(챕터 포함) 등록·수정·삭제
- 스레드 소속 추가·제거, 스레드 등록·수정·삭제, 라이프사이클 변경
- 댓글 작성·수정·삭제

Keep(`prospective`) 쓰기는 2단계의 첫 대상으로 따로 계획한다(§1.4).

로그인·인증 상태 확인·토큰 갱신·로그아웃은 앱 접근을 위한 인증 흐름이므로 범위 안이다(§2). 복사·내보내기는 서버 데이터를 바꾸지 않으므로 읽기 기능으로 본다(§8).

### 1.3 구현됨, 실기기 미검증

다음 항목은 코드에 반영되었지만 실기기(에뮬레이터 포함)에서 아직 확인하지 않았다. 확인 항목은 §11을 따른다.

| 항목 | 내용 | 절 |
|---|---|---|
| 상세 화면 태그 | 엔트리 상세 본문 아래 `태그`(꿈은 `꿈 태그`)·`스레드`·`일자 태그` 행. 태그 칩은 태그별 기록 화면을, 스레드 칩은 스레드 글 목록을 연다 | §4.5 |
| 기간 스레드 섹션 | 기간 태그 패널 아래 접이식 `이 날의 스레드` / `이 주의 스레드` / `이 달의 스레드`. 웹 `JournalPeriodThreadSummary.vue` 대응. 칩을 누르면 스레드 글 목록 | §5.9 |
| 스레드 글 목록 | `ThreadResultScreen`. 기간 스레드 섹션 칩·엔트리 스레드 칩을 누르면 열린다. 스레드 정보 + 소속 엔트리 날짜별(기본 최신순) | §4.9 |
| 복사·공유 | 엔트리 상세, 일·주·월 보기, 검색 결과, 태그별 기록, 스레드 글 목록의 `복사`·`공유`. 웹 복사 규칙(전체 모드) | §4.8 |
| 태그별 기록 (태그 검색 복구) | `TagResultScreen`. 패널·칩의 태그와 검색 탭 태그 매칭 칩을 누르면 열린다 | §4.4.2 |
| 검색 태그 매칭 | 검색 탭에서 키워드를 검색하면 이름이 맞는 태그 칩을 엔트리 결과 위에 표시 | §4.4.1 |
| 햄버거 메뉴 | 탭·메뉴 화면 헤더 왼쪽 `☰` → 왼쪽 드로어. 웹 사용자 사이드바 메뉴 전체(관리자 제외)를 같은 묶음·이름·순서로 표시 | §4.10 |
| 저널 스레드 목록 · 저널 결산 | 햄버거 메뉴의 `저널 스레드`·`저널 결산`이 여는 읽기 전용 화면(`ThreadListScreen`, `AnnualListScreen` → `AnnualDetailScreen`). Keep 외 나머지 사용자 메뉴는 `준비 중` 화면 | §4.11~§4.13 |
| Keep 전수관리 (2-0, 읽기 전용) | 햄버거 메뉴의 `Keep 전수관리`가 여는 `KeepHomeScreen`(Project 칩 · `진행/기한/종결` · 검색·필터 · 목록 복사) → `KeepDetailScreen`(전체 필드·본문·복사/공유). 쓰기 없음. 에뮬레이터에서도 아직 확인하지 않았다 | §4.14, §4.15 |

에뮬레이터(Android, Expo Go)에서는 햄버거 메뉴·스레드 목록·결산 목록/상세·`준비 중` 화면을 2026-10-06에 한 번 확인했다(§11). 실기기와 iOS는 확인하지 않았다.

남은 일은 스레드 상세 강화(§4.7)와 웹 대비 빠진 복사·내보내기(챕터 단위 복사, 해석 포함 범위 선택, TXT 파일 내보내기, §4.8)다. 세부 단계와 진행 현황은 [`tagcloud-thread-port-plan.md`](./tagcloud-thread-port-plan.md) §6을 따른다.

### 1.4 다음 단계 (2단계) — Keep 할일

2단계의 첫 대상은 웹 `Keep 전수관리`(`/keep`)를 옮긴 모바일 할일(Keep) 화면이다. 읽기 전용 목록·상세(2-0) → 완료 토글·라이프사이클(2-1) → 빠른 추가(2-2) → 편집(2-3) 순으로, 쓰기는 Keep에 한해 단계별로 연다. **2-0은 구현했다(구현·미검증)**: 드로어의 `Keep 전수관리`가 `준비 중` 대신 Keep 목록(§4.14)을 열고, 항목을 누르면 Keep 상세(§4.15)가 열린다. 쓰기 호출·체크박스·스와이프는 없다(§8). 웹 분석·API(읽기/쓰기)·화면 구성안·결정이 필요한 질문은 [`keep-todo-plan.md`](./keep-todo-plan.md)를 따른다.

## 2. 계약 경계와 SSOT

| 자산 | 소유 계약 |
|---|---|
| `docs/migration/mobile/screen-spec.md` | 모바일 화면, 탐색 흐름, 조회 전용 경계 |
| `docs/migration/journal/screen-spec.md` | 웹 저널 화면과 웹 전용 레이아웃 |
| `docs/migration/journal/interaction-spec.md` | 웹 저널 인터랙션 |
| 백엔드 저널·인증 API | 사용자 소유권, 날짜 범위, 검색 조건, 응답 데이터 의미, 세션 정책 |

모바일은 서버 응답을 표시·탐색하는 클라이언트다. 날짜 범위, 태그 종류, 엔트리 유형과 검색 결과의 의미를 클라이언트에서 별도로 재해석하거나 임시 데이터로 보정하지 않는다.

웹과 규칙을 맞추는 항목은 다음으로 한정한다.

| 항목 | 웹 기준 | 모바일 절 |
|---|---|---|
| 로그인 화면 배경·문구·필수 입력 안내 | `frontend-vue` `AuthLayout` + `SignIn.vue`, `messages_ko.properties` `auth.login.*` | §4.2 |
| 주·월 목록 정렬 기본값(최신 날짜 먼저) | `stores/journal.ts` `sortOrder` 기본 `DESC` | §5.5 |
| 챕터 헤더 라벨 | `JournalChapterItem.vue` 헤더 | §6.4 |
| 기간 태그 클라우드 (일자·일기·꿈 3행, 크기·색) | `JournalTagCloudHeader.vue`, `TagCloud.vue`, `styles/components/tag.scss` | §5.7 |
| 인라인 태그 표기 `#[카테고리]태그명` | `TagChip.vue` | §5.8 |

조회 전용 경계는 저널 데이터에 적용한다. 로그인, 인증 상태 확인, 토큰 갱신, 로그아웃은 앱 접근을 위한 인증 흐름이므로 저널 쓰기로 취급하지 않는다.

## 3. v0.1 구현 현황

현황 표기는 합의된 v0.1 계약에 대해서만 사용한다.

- ✓: 계약 충족
- ⚠: 일부 충족
- ❌: 계약 미충족
- `구현·미검증`: 코드에 반영되었지만 실기기에서 확인하지 않음(§11). 확인을 마치면 ✓로 바꾼다.

| 계약 | 현황 | 확인 근거 |
|---|:---:|---|
| 인증 후 조회 화면 진입 | ✓ | `AuthContext`가 앱 시작 시 `get-auth-info`로 세션을 확인하고, `AppNavigator`가 인증 상태에 따라 `LoginScreen`과 메인 탭을 전환한다. 시작 시 401은 비로그인 정상 흐름이다(§7.3). |
| 로그인 화면 | ✓ | `LoginScreen`이 웹 로그인 배경·문구·필수 입력 안내와 키보드 회피를 적용한다(§4.2). |
| 웹·모바일 세션 공존 | ✓ | 모든 REST 요청이 `X-Client-Channel: MOBILE`을 보내고, 백엔드가 중복 로그인·최대 세션을 채널(WEB/MOBILE)별로 판단한다(§7.2). |
| 일별 조회 | ✓ | `TodayScreen` 기본 모드 `JournalDailyView`가 `viewType=DAILY&stdrdDt`로 선택한 하루를 조회한다. |

| 저널 조회 전용 | ✓ | 모바일 화면과 API 파사드가 저널 조회 요청만 수행하며, 생성·수정·삭제 화면과 해당 API 호출이 없다. |

## 4. 화면 구조

로그인 후에는 하단 탭 세 개와, 탭 위에 쌓이는 스택 화면(상세 읽기, 태그별 기록, 스레드 글 목록, 메뉴 화면, Keep 목록·상세)을 제공한다. 웹 사용자 메뉴는 헤더 왼쪽 `☰` 햄버거 메뉴(§4.10)로 연다. 하단 탭은 `오늘 · 검색 · 나` 세 개를 유지한다(§4.7).

```text
인증(로그인)
  └─ 메인 탭
       ├─ 오늘  : 날짜 조회 (일·주·월) + 기간 태그·스레드 + 복사·공유 ─┐
       ├─ 검색  : 키워드 검색 ─────────────────────────────────────┼─ 상세 읽기 (스택)
       └─ 나    : 이번 달 통계 · 로그아웃                           │
     태그 패널·태그 칩·검색 태그 칩 ──→ 태그별 기록 (스택) ─ 날짜 헤더 → 오늘 탭 ┤
     스레드 섹션·스레드 칩 ──→ 스레드 글 목록 (스택) ──── 날짜 헤더 → 오늘 탭 ┘

  ☰ 햄버거 메뉴 (오늘·검색·나 탭 헤더, 메뉴 화면 헤더)
       저널 ─ 저널 일자   → 오늘 탭
            ├ 저널 스레드 → 저널 스레드 목록 (스택) ─→ 스레드 글 목록 (스택)
            └ 저널 결산   → 저널 결산 목록 (스택) ──→ 결산 상세 (스택)
       Keep ─ Keep 전수관리 → Keep 목록 (스택) ────→ Keep 상세 (스택)
       일반게시판 · 일정 (그 밖의 사용자 메뉴) → 준비 중 (스택)
```

| 탭 | 라벨 | 화면 | 역할 |
|---|---|---|---|
| `Today` (기본 탭) | 오늘 📖 | `TodayScreen` | 날짜 조회 허브. 일·주·월 토글, 기간 태그 클라우드 패널, 기간 스레드 섹션, 복사·공유 바, 엔트리 목록 |
| `Search` | 검색 🔍 | `SearchScreen` | 키워드 엔트리 검색 |
| `Profile` | 나 👤 | `ProfileScreen` | 사용자 정보, 이번 달 통계, 로그아웃 |

- 탭 바 선택 표시(`AppNavigator`의 `MainTabs`): 선택한 탭은 탭 항목 전체에 둥근 배경을 깐다 — `tabBarActiveBackgroundColor: colors.surface` + `tabBarItemStyle: { borderRadius: 14, marginHorizontal: 10, marginVertical: 4 }`. 선택 탭 라벨은 강조색(`colors.accent`, `tabBarActiveTintColor`)에 굵게(800), 비선택 탭은 아이콘 불투명도 0.4와 흐린 라벨(`colors.muted`)이다. 아이콘이 이모지라 tint 색이 먹지 않으므로 선택 강조는 항목 배경으로 한다. 아이콘 자체에 패딩·배경을 주면 탭 바의 고정 아이콘 영역에서 잘려 아이콘이 사라지므로 그렇게 하지 않는다.
- 상세 읽기(`EntryDetail`), 태그별 기록(`TagResult`, 파라미터 `{ tagId, name, ctgr?, kind: "day" | "diary" | "dream" }`), 스레드 글 목록(`ThreadResult`, 파라미터 `{ threadId, title }`)은 루트 스택 화면이며 `slide_from_right`로 열린다. 태그별 기록은 `openTagResult`, 스레드 글 목록은 `openThreadResult`(`src/navigation/threadResult.ts`)가 `StackActions.push`로 열어, 같은 화면에서 다른 태그·스레드를 눌러도 새 화면이 쌓인다. 태그 ID가 숫자가 아니거나 이름이 비어 있으면, 스레드 ID가 숫자가 아니면 열지 않는다. `title`은 스레드 정보를 받기 전 임시 제목이다(비어 있어도 연다).
- 태그 탭(`Tag`)은 제거했고 `TagExploreScreen.tsx`는 삭제했다. 스레드 목록은 탭 대신 햄버거 메뉴의 `저널 스레드`로 연다(§4.7, §4.11).
- 메뉴 화면 — 저널 스레드 목록(`ThreadList`), 저널 결산 목록(`AnnualList`), 결산 상세(`AnnualDetail`, 파라미터 `{ yy, title? }`), Keep 목록(`KeepHome`), Keep 상세(`KeepDetail`, 파라미터 `{ id, item?, projectTitle? }` — `item`·`projectTitle`은 목록에서 넘기는 표시용 초기값), 준비 중(`MenuPlaceholder`, 파라미터 `{ menuName, groupName?, url? }`) — 도 루트 스택 화면이며 `slide_from_right`로 열린다. 햄버거 메뉴에서 열 때는 `CommonActions.navigate({ name, params, pop: true })`라 같은 화면이 이미 스택에 있으면 그 화면으로 돌아가고(위의 화면은 닫힘), 없으면 쌓는다. 메뉴를 오가도 스택이 끝없이 깊어지지 않는다. 결산 상세는 결산 목록에서, Keep 상세는 Keep 목록에서 `push`한다.
- 오늘 탭은 `{ date }` 파라미터를 받으면 일 모드로 전환해 그 날짜를 표시하고(1회 소비), 미래 날짜는 오늘로 수렴한다. 태그별 기록·스레드 글 목록의 날짜 헤더가 `navigateToDailyHub`로 이 파라미터를 넘긴다. `popTo("Main")`이라 위에 쌓인 스택 화면(태그별 기록·상세)을 닫고 기존 메인 탭으로 돌아간다(새 메인을 쌓지 않음).

### 4.1 공통 레이아웃

- `App.tsx`가 `SafeAreaProvider`로 앱 전체를 감싸고, 모든 화면은 `react-native-safe-area-context`의 `SafeAreaView`를 사용한다. React Native 내장 `SafeAreaView`는 사용하지 않는다.
- 탭 화면(오늘·검색·나)은 `edges={["top", "left", "right"]}`만 적용한다. 하단 여백은 탭 바가 처리한다.
- 태그별 기록·스레드 글 목록 화면은 탭 바가 없으므로 네 변(`top`·`left`·`right`·`bottom`)을 모두 적용한다. 메뉴 화면(§4.11~§4.13)도 같다.
- 탭 화면 헤더: `DreamDiary` 키커 왼쪽에 `☰` 버튼(`AppMenuButton`, 34×34)을 둔다. 메뉴 화면 헤더는 `MenuScreenHeader` — `‹`(뒤로 갈 화면이 있을 때) + `☰` + 제목 한 줄.

### 4.3 날짜 조회 (오늘 탭)

날짜 조회 화면은 일별·주별·월별 보기와 기준 날짜 또는 기간 선택을 제공한다. 일·주·월 보기는 하나의 화면에서 `일 | 주 | 월` 토글로 전환하며, **일별 보기가 기본(주 보기)이다.**

각 보기는 서버가 반환한 날짜별 저널 구조를 유지하며, 사용자는 표시된 엔트리에서 상세 읽기로 진입할 수 있다. 세부 계약은 §5를 따른다.

### 4.4 검색

검색은 키워드 검색(검색 탭)과 태그 검색(태그별 기록 화면) 두 축으로 계약한다. 태그 검색은 태그 탭 제거 후 태그별 기록 화면으로 복구했다(§4.4.2, 실기기 미검증). 검색 탭은 키워드와 이름이 맞는 태그를 칩으로 보여주어 태그별 기록으로 이어 준다(§4.4.1 태그 매칭, 실기기 미검증).

#### 4.4.1 키워드 검색

- 입력한 키워드로 서버의 저널 엔트리를 검색한다. 키워드가 비어 있으면 검색을 실행하지 않는다.
- **검색 제출 (결정)**: 검색(엔트리 결과와 태그 매칭 모두)은 `검색` 버튼 또는 키보드의 검색 키(`returnKeyType="search"`, `onSubmitEditing`)로만 실행한다. 입력하면서 검색하지 않는다(search-as-you-type 없음) — 글자를 입력·수정하기만 해서는 요청이 나가지 않는다.
- 유형 필터는 `일기 | 꿈` 두 가지이며 **기본값은 일기**다. 이미 검색을 제출한 뒤 필터를 바꾸면 **마지막으로 제출한 검색어**로 다시 검색한다(입력창에서 고치는 중인 글자는 쓰지 않음). 제출한 적이 없으면 필터만 바뀐다.
- 화면에 다시 들어오면(탭 복귀·상세에서 뒤로) 마지막으로 제출한 검색을 새로 고친다. 제출한 검색이 없으면 요청하지 않는다.
- **지우기·초기화 (결정, 에뮬레이터 확인)**:
  - 입력창 오른쪽 `✕`(입력이 있을 때만 표시): 입력 글자만 지우고 입력창에 포커스를 둔다. 결과·태그 칩·마지막 검색 조건은 그대로다.
  - 필터 줄 오른쪽 `초기화`(검색을 제출한 뒤에만 표시): 입력·결과·태그 칩·마지막 검색 조건을 비우고 검색 전 상태로 돌아간다. **일기/꿈 필터는 그대로 둔다.** 진행 중인 요청의 응답은 버린다.
- 예전의 `전체` 필터는 제거했다. `GET /api/journal/entries`는 `type`(`DIARY` 또는 `DREAM`)이 필수이며, `type` 없이 호출하면 백엔드가 `type is required.`로 400을 반환하기 때문이다. 웹도 항상 `type`을 보낸다([`api-contract-audit.md`](./api-contract-audit.md) 고영향 1번).
- 검색 실행 전 idle 상태와 결과 0건 상태를 구분한다.
- 결과 항목은 유형·기준 날짜(`entry.stdrdDt`가 있을 때 `YYYY.MM.DD`)·제목·본문 미리보기를 표시하고, 선택하면 상세 읽기로 이어진다. 검색 응답의 `stdrdDt` 유무는 실기기 확인 항목이다(§11). 상세로 `dayTags`를 넘기지 않으며, 결과 카드에는 태그 칩을 표시하지 않는다.
- 결과 순서 (구현·미검증): `stdrdDt` 내림차순(최신 먼저)으로 표시한다. 같은 날짜와 날짜 없는 결과는 서버 순서를 유지하며, 날짜 없는 결과는 맨 뒤다. 검색 API는 페이지 없이 전체 결과를 돌려주므로 화면·복사 모두 전체 결과다.
- 결과 복사·공유 (구현·미검증): 결과가 있으면 결과 목록 위에 `JournalCopyShareBar`(라벨 `검색 결과`)를 둔다(§4.8). 결과가 없거나 조회 실패면 숨긴다.

**태그 매칭 (구현·미검증)**

검색을 실행하면 엔트리 결과 위에 검색어와 이름이 맞는 태그를 칩으로 표시한다. 칩을 누르면 태그별 기록(§4.4.2)을 연다(종류 = 칩 종류).

- 서버에 태그 이름 검색·자동완성 API가 없다(`TagSearchParam`에 이름 조건이 없음). 웹도 태그 셀렉터에서 카탈로그 전체를 받아 화면에서 거른다(`useSearchTagCatalog`). 모바일도 같은 방식이다.
  - 일자 태그: `GET /api/journal/day/tags`(기간 파라미터 없음 → 사용자 일자 태그 전체, 웹 `JournalDayMetaModal` 태그 카탈로그와 같은 요청) — `getJournalDayTagCatalog`
  - 일기·꿈 태그: `GET /api/journal/entry/tags?type=DIARY|DREAM`(기간 없음 → 서버 `getMyTagList`, 웹 `useSearchTagCatalog`와 같은 요청) — `getJournalEntryTagCatalog`
- 유형 필터와의 관계 (사용자 결정): **`일기` 필터는 일기 태그 + 일자 태그, `꿈` 필터는 꿈 태그만** 보여준다(꿈 검색에는 일자 태그를 넣지 않는다). 일기 필터에서는 `일기 태그` 줄 다음 `일자 태그` 줄로 나누고, 칩 색은 종류 색이다(§5.8).
- 매칭: 마지막으로 실행한 검색어(입력 중인 글자 아님)로 부분 일치한다. 대소문자를 무시하고 공백은 `_`와 같게 본다(웹 태그명 정규화). 정렬은 이름 정확 일치 → 앞부분 일치 → 사용 빈도(`contentSize`) 내림차순 → 이름순이며 같은 `tagId`는 한 번만 둔다.
- 개수: 머리줄 `태그 N개`. 종류별로 처음 8개만 보이고 넘치면 `더보기 (+N) ▾`로 전부 펼친다(`접기 ▴`). 검색어나 필터가 바뀌면 다시 접고, 이전 검색의 태그 칩은 바로 지운다.
- 일치하는 태그가 없으면 영역 전체를 숨긴다. 카탈로그를 받는 중이고 아직 보일 태그가 없으면 `태그 찾는 중…`을 작게 표시한다.
- 엔트리 검색과 따로 조회한다. 엔트리 쪽이 실패해도 태그는 표시하고 그 반대도 같다. 태그 카탈로그가 전부 실패하면 `태그 목록을 불러오지 못했습니다.`, 일부만 실패하면(일기 필터의 일기·일자 중 하나) 받은 쪽 칩과 함께 `일부 태그 목록을 불러오지 못했습니다.`를 작게 표시한다(조용히 숨기지 않음). 401은 오류 로그를 남기지 않는다. 늦게 도착한 응답은 버린다.
- 카탈로그는 화면 안에서 종류별로 60초 동안 재사용하고, 같은 카탈로그를 받는 중이면 그 요청을 같이 쓴다(필터 전환·재검색·탭 복귀 시 다시 받지 않음). 실패는 캐시하지 않는다.
- **버그 수정 기록 (2026-10-06, 에뮬레이터 확인)**: `dreamdiary`를 일기 필터로 검색하면 `142건`만 나오고 태그 칩이 없던 문제.
  - 서버·데이터는 정상이었다: DB에 `dreamdiary` 태그(id 1086)가 일자 태그 127건·일기 태그(살아 있는 링크 6건)로 연결돼 있고, 기간 없는 `/api/journal/day/tags`·`/api/journal/entry/tags?type=DIARY`는 기간 조건 없이 전체 태그를 돌려준다(`TagSearchParam`·`JournalDayTagQuery`·`Journal*TagSpec` 확인, 같은 조건의 SQL로 일자 태그 197개 중 포함 확인). 응답 모양(`rsltList`·`id`·`name`)도 `normalizeTagList`와 맞는다.
  - 직접 원인: 에뮬레이터의 Expo Go가 Metro에 `223.131.148.20:8082`(PC 공인 IP)로 붙어 있다가 연결이 끊겨(`Cannot connect to Expo CLI`) 태그 매칭이 들어가기 전 번들을 계속 실행하고 있었다(화면에 결과 복사 바도 없었음). `adb reverse tcp:8082 tcp:8082` 후 `exp://127.0.0.1:8082`로 다시 열자 같은 검색에서 `일기 태그 #dreamdiary`·`일자 태그 #dreamdiary` 칩이 나왔다.
  - 함께 고친 화면 쪽 결함: ① 포커스 효과가 입력 글자(`keyword`)에 의존해 검색을 한 번 제출한 뒤에는 글자마다 엔트리·태그 검색이 다시 나갔다(→ 제출 시에만 검색). ② 같은 카탈로그를 동시에 여러 번 받았다(→ 진행 중 요청 공유). ③ 태그를 받는 동안 아무 표시가 없었고 일부 실패는 안내가 없었다(→ `태그 찾는 중…`·일부 실패 안내).

#### 4.4.2 태그 검색 — 태그별 기록 화면 (구현·미검증)

`TagResultScreen`(헤더 `태그별 기록`)은 웹 태그 메뉴의 "검색"을 읽기 전용 스택 화면으로 옮긴 것이다. 삭제한 `TagExploreScreen`의 결과 로직을 대신한다.

**진입**

- 기간 태그 클라우드 패널의 태그(§5.7), 엔트리 카드·일자 헤더의 태그 칩(§5.8), 엔트리 상세의 태그 칩(§4.5), 태그별 기록·스레드 글 목록 결과 카드 안의 태그 칩, 검색 탭 태그 매칭 칩(§4.4.1)에서 연다.
- 종류(`kind`)는 누른 위치가 정한다: 일자 태그 `day`, 일기 태그 `diary`, 꿈 태그 `dream`.
- 검색 탭에서 태그로 엔트리를 거르는 필터는 없다(태그 매칭 칩은 이 화면으로 이동만 한다).

**태그 정보 카드**

- 종류 라벨(`일자 태그` / `일기 태그` / `꿈 태그`)과 `#[카테고리]이름`을 종류별 칩 색으로 표시한다.
- 태그 설명: `GET /api/tags/{tagId}/profile?contentType=JOURNAL_DAY|JOURNAL_DIARY|JOURNAL_DREAM`의 `content`를 표시한다(웹 태그 프로필의 읽기 부분만, 편집·삭제 없음). HTML이면 텍스트로 바꾸고, 비어 있거나 조회에 실패하면 설명 줄을 생략한다(실패는 화면 오류로 보지 않음).

**결과 조회**

| 종류 | 요청 | 연도 |
|---|---|---|
| 일자 태그 | `GET /api/journal/day/tag/{tagId}/years` → `GET /api/journal/days?viewType=SEARCH&tagId=&yy=` | 서버 연도 목록. 기본값은 올해가 목록에 있으면 올해, 없으면 가장 최근 연도(목록 조회 실패 시 올해). `전체`는 `yy` 생략 |
| 일기·꿈 태그 | `GET /api/journal/entries?tagIds=&type=DIARY\|DREAM` | 결과 엔트리의 `stdrdDt`에서 뽑은 연도로 화면에서 거른다. 기본값 `전체` |

- 연도 선택은 `전체`·`YYYY년` 가로 칩 줄이다. 일자 태그는 항상 표시하고, 일기·꿈 태그는 고를 연도가 있을 때만 표시한다.
- 결과는 날짜별로 묶어 최신 날짜부터 표시한다. 요약 줄은 일자 태그 `N일`, 일기·꿈 태그 `N일 · M건`이다.
- 일자 태그 결과: 각 일자에 그 날의 일자 태그 칩과 엔트리(챕터 순 → 꿈, 다른 엔트리에 붙은 해석은 중복 제외)를 표시한다. 엔트리가 없으면 `엔트리 없음`. SEARCH 응답에 엔트리가 담겨 오는지는 실기기 확인 항목이다(§11).
- 일기·꿈 태그 결과: 같은 날짜의 엔트리를 `sortOrder` 순으로 묶는다. `stdrdDt`가 없는 엔트리는 `날짜 없음` 묶음으로 모인다.
- 결과 카드: `일기`/`꿈` + `#순번`, 본문 미리보기(3줄, 140자), 엔트리 태그 칩, 소속 스레드 칩(누르면 스레드 글 목록, §4.9).
- 빈 결과: `이 태그가 붙은 날이 없습니다.`(일자) / `이 태그가 붙은 기록이 없습니다.`(일기·꿈). 실패: 오류 문구와 `다시 시도`. 당겨서 새로고침을 지원하며 늦게 도착한 응답은 버린다.
- 복사·공유 (구현·미검증): 표시 중인 엔트리가 1건 이상이면 요약 줄 위에 `JournalCopyShareBar`(라벨 `이 태그 기록`)를 둔다. 선택한 연도의 화면 결과를 화면 순서 그대로 복사한다(§4.8).

**이동**

- 날짜 헤더(`YYYY-MM-DD (요일)` + `이 날 보기 ›`)를 누르면 오늘 탭 일 모드로 그 날짜를 연다(§4 `navigateToDailyHub`).
- 엔트리를 누르면 상세 읽기를 push한다. 일자 태그 결과에서는 그 날의 일자 태그를 `dayTags`로 함께 넘긴다.

#### 4.4.3 검색 결과 상태

- 조회 중, 결과 0건, 조회 실패를 서로 다른 상태로 표시한다.
- 조회 실패를 빈 결과로 보정하지 않으며, 재검색 또는 재시도로 다시 조회할 수 있다.

### 4.5 상세 읽기

상세 화면은 선택한 엔트리의 서버 확정 데이터를 표시한다.

- 기준 날짜
- 엔트리 유형 (`contentType` 라벨 배지)
- 제목
- 본문
- 태그·스레드 (구현·미검증): 웹 엔트리 상세처럼 본문 아래 묶음 영역에 다음 행을 표시한다. 데이터는 내비게이션 파라미터(`entry`, `dayTags`)에서 가져온다. 별도 API는 스레드 글 목록에서 들어온 경우의 소속 스레드 재조회 하나뿐이다. 값이 없는 행은 그리지 않고, 셋 다 없으면 영역을 그리지 않는다.
  - `태그`(꿈 엔트리는 `꿈 태그`): `entry.tag.list` 칩. 누르면 태그별 기록(`diary`/`dream`)을 연다.
  - `스레드`: `entry.threadList` 칩. 누르면 그 스레드의 글 목록(§4.9)을 연다. 스레드 소속 엔트리 API 응답에는 `threadList`가 비어 오므로, 스레드 글 목록에서 들어온 경우 화면이 진입한 스레드를 `threadList`에 채워 넘기고 파라미터 `loadThreads: true`를 준다. 상세는 이때 `GET /api/journal/entries/{entryId}/threads`로 소속 스레드 전체를 다시 읽어 바꾼다. 재조회가 실패하면 진입한 스레드 칩만 남기고 경고 로그만 남긴다(401 제외).
  - `일자 태그`: 일·주·월 목록이나 일자 태그 결과에서 들어온 경우에만 받는 `dayTags`(그 엔트리가 속한 일자의 `day.tag.list`) 칩. 누르면 태그별 기록(`day`)을 연다. 키워드 검색·일기/꿈 태그 결과에서 들어오면 전달되지 않는다.
  - 칩 형식과 정규화는 §5.8과 같다.
- 헤더 오른쪽 `복사`·`공유` (구현·미검증): §4.8.

꿈 엔트리는 꿈 전용 색으로 구분한다. 응답에 값이 없는 선택 필드는 빈 UI를 억지로 채우지 않는다. 본문은 사용자가 기록 내용을 읽을 수 있도록 화면 너비 안에서 스크롤 가능한 형태로 표시한다.

### 4.6 나 (프로필)

- 로그인 사용자 정보와 이번 달 통계(기록 일수·꿈·일기 수)를 표시한다. 집계 기준은 §6.5를 따른다.
- 통계 조회 실패는 통계 영역에만 표시하고 0으로 보정하지 않는다.
- 로그아웃은 확인 대화상자(`정말 로그아웃 하시겠습니까?`)를 거친 뒤 실행하며, 인증 흐름이므로 조회 전용 경계와 충돌하지 않는다.

### 4.7 탭 재편 (결정, 일부 구현)

탭 구성을 `오늘 · 스레드 · 검색 · 나`로 재편하기로 **결정했다**([`tagcloud-thread-port-plan.md`](./tagcloud-thread-port-plan.md) §4.3 권장안). 판단 근거는 엔트리와 그 기간의 태그를 한 화면에서 보는 것이다. 그래서 별도 태그 탭을 없애고 기간 태그를 오늘 탭 안으로 옮겼다.

| 탭 | 목표 구성 | 현재 상태 |
|---|---|---|
| 오늘 | 일/주/월 보기 + 날짜 선택 피커 + 접이식 기간 태그 클라우드 패널 + 기간 스레드 섹션 + 복사·공유 바 + 엔트리 목록(엔트리 태그·소속 스레드 칩) | 구현됨. 기간 스레드 섹션(§5.9)·복사·공유 바(§4.8)는 실기기 미검증. |
| 스레드 | 스레드 목록(말머리 탭·라이프사이클 필터·제목 검색) → 스레드 상세 | **탭 대신 햄버거 메뉴**(2026-10-06): 하단 탭은 `오늘 · 검색 · 나` 세 개를 유지하고, 스레드 목록은 햄버거 메뉴 `저널 > 저널 스레드`가 여는 스택 화면(§4.11, 제목 검색만, 말머리 탭·라이프사이클 필터 없음)으로 제공한다. 스레드 상세에 해당하는 스레드 글 목록(§4.9)은 목록·기간 스레드 섹션·스레드 칩에서 열린다. |
| 검색 | 키워드 검색 + 태그 검색(기존 태그 탭의 전체 기간 탐색 흡수) | 키워드 검색 구현. 태그 검색은 태그별 기록 스택 화면(§4.4.2)으로 복구(미검증). 검색 탭 안 태그 입력은 없음. |
| 나 | 프로필·이번 달 통계·로그아웃 | 구현됨. |

남은 일:

- 태그 누름 동작: 지금은 누르면 바로 태그별 기록 화면(전체 기간 + 연도 선택)을 연다. 포팅 계획의 액션 시트("이 기간에서 보기 / 전체 기간 검색 / 연도별 일자 보기")는 두지 않았다(포팅 계획 1-3단계).
- 스레드: 스레드 목록의 말머리 탭·라이프사이클 필터와 상세 강화(연관 스레드 표시 등, 포팅 계획 1-4단계). 스레드 목록(햄버거 메뉴, §4.11), 기간 스레드 섹션·엔트리 스레드 칩의 누름 동작과 스레드 글 목록 화면은 구현했다(§4.9, 실기기 미검증).
- 단계·API·열린 질문은 포팅 계획 문서를 따른다.

### 4.8 복사·공유 (구현·미검증)

1단계 성공 기준(§1.1)에 포함한다. 텍스트는 클라이언트에서 조립하며 서버 내보내기 API는 호출하지 않는다.

**위치**

| 위치 | 버튼 | 대상 | 공유 시트 제목 |
|---|---|---|---|
| 엔트리 상세 헤더 오른쪽 | `복사` · `공유` | 그 엔트리 1건 | `YYYY.MM.DD {유형}` |
| 일 보기 (`JournalCopyShareBar`, 라벨 `이 날 기록`) | `복사` · `공유` | 그 날의 엔트리 | `YYYY-MM-DD 기록` |
| 주 보기 (`이 주 기록`) | `복사` · `공유` | 그 주의 일자들 | `{기간 라벨} 기록` |
| 월 보기 (`이 달 기록`) | `복사` · `공유` | 그 달의 엔트리가 있는 일자들 | `{YYYY년 M월} 기록` |
| 검색 탭 (`검색 결과`) | `복사` · `공유` | 현재 검색 결과 전체(검색 API는 페이지 없음) | `검색 {검색어}` |
| 태그별 기록 (`이 태그 기록`) | `복사` · `공유` | 선택한 연도의 화면 결과 | `{종류 라벨} {태그명}` |
| 스레드 글 목록 (`이 스레드 글`) | `복사` · `공유` | 스레드 소속 엔트리 전체 | `스레드 {제목}` |
| Keep 목록 (`{진행\|기한\|종결} N건`, §4.14) | `복사` · `공유` | 현재 Project 범위·보기·필터 결과(화면 순서) | `Keep {보기}` |
| Keep 상세 헤더 오른쪽 (§4.15) | `복사` · `공유` | 그 Keep 1건 | `Keep {제목}` |

- 기간 바는 스레드 섹션 아래, 목록 위에 두며 조회가 끝나 오류가 없고 엔트리가 있을 때만 표시한다.
- 결과 목록 바(검색·태그별 기록·스레드 글 목록)는 결과 목록 위에 두며, 조회가 끝나 오류가 없고 엔트리가 1건 이상일 때만 표시한다. 성공 알림은 건수를 담는다(`검색 결과 N건을 복사했습니다.`, `태그 기록 N건을 복사했습니다.`, `스레드 글 N건을 복사했습니다.`).
- `복사`는 `expo-clipboard`의 `setStringAsync`로 클립보드에 넣고 `복사했습니다.`를 알린다(Android 토스트, iOS 알림창). 실패하면 `복사하지 못했습니다.`
- `공유`는 React Native `Share.share`로 시스템 공유 시트를 연다(메신저·메모·파일 저장 등은 시트의 대상 앱이 처리). 실패하면 `공유하지 못했습니다.`
- 텍스트가 비어 있으면 `복사할 내용이 없습니다.` / `공유할 내용이 없습니다.`를 알리고 아무것도 하지 않는다.

**텍스트 규칙** (`src/utils/journalCopy.ts`, 웹 복사 계약 포트)

- 본문: `content`(HTML) 우선, 없으면 `markdownContent`. 웹 `htmlToPlainText`와 같은 규칙으로 구조 태그(`p`·`br`·`div`·`li`·`hr`)만 줄바꿈으로 바꾸고 엔티티를 한 번 디코딩하며, 빈 문단은 사용자가 만든 개행으로 보존한다.
- 줄바꿈은 웹과 같은 `CRLF`이고 블록 사이는 빈 줄 1개다.
- 날짜 줄은 `YYYY-MM-DD (요일)`이며 요일은 웹 한국어 메시지와 같은 한자(日月火水木金土)다.
- 엔트리 1건(웹 `useEntryCopy.copyEntry`): 날짜 줄 → 본문 → 해석(리플렉션) 본문.
- 여러 엔트리(웹 엔트리 검색 `copyAll`·스레드 복사와 같은 블록 계약): 날짜가 바뀔 때만 날짜 줄, 각 엔트리는 `#순번` + 본문(+ 해석), 엔트리 사이 빈 줄. 한 일자 안은 챕터 순 → 꿈 순이고, 다른 엔트리의 해석으로 이미 붙은 해석 엔트리는 중복하지 않는다. 주·월은 일자 오름차순이다(화면 목록은 내림차순).
- 결과 목록(검색·태그별 기록·스레드 글 목록, `buildResultListCopyText`): 머리줄 다음 빈 줄, 이어서 **화면에 보이는 순서 그대로** 엔트리 블록. 날짜가 바뀔 때만 날짜 줄(날짜 없는 엔트리는 날짜 줄 없음), 각 엔트리는 `유형 #순번 · 제목`(순번·제목은 있을 때만, 유형은 `일기`/`꿈`/`노트`/`해석`) 줄 + 본문(+ 해석), 엔트리 사이 빈 줄.
  - 머리줄 — 검색: `검색: "{검색어}" · {일기|꿈} · N건` / 태그별 기록: `{종류 라벨} #[카테고리]태그명` + `{YYYY년|전체 연도} · N일 · M건` / 스레드 글 목록: `스레드: [말머리] 제목` + `{소속 기간} · 소속 엔트리 N건 · {최신순|오래된순}`.
- Keep(`src/utils/keepCopy.ts`): 웹 Keep에는 복사 기능이 없어 위 저널 규칙(CRLF, 블록 사이 빈 줄 1개)에 맞춰 새로 정했다.
  - 1건: `★ [말머리] 제목`(★은 중요일 때) → `상태: {라이프사이클} · {중요} · {요구}` → `기한: YYYY-MM-DD · D-n`(진행 중일 때만 D-day) → `일시:` · `위치:` · `Project:` · `태그: #[카테고리]이름 …` · `등록: YYYY.MM.DD HH:mm`(값이 있는 줄만) → 빈 줄 → 본문(마크다운 → 평문).
  - 목록: 머리줄 `Keep 전수관리 · {보기} · {Project 범위} · N건`(+ 조건이 있으면 `조건: …`) → 빈 줄 → 항목마다 `- ★ [말머리] 제목 · {보류|완료|실패|만료|내려놓음} · {요구}` + 들여쓴 `  기한 ~MM/DD · D-n · 일시 … · Project … · #태그` 줄. 기한 보기는 묶음마다 `[지남]`·`[오늘]`·`[7일 이내]`·`[그 이후]` 머리, 묶음 사이 빈 줄. 본문은 넣지 않는다.
- 해석 포함 범위는 웹 주 버튼과 같은 **전체(full)** 모드만 쓴다. 코드에는 `no-pending`(보류 제외)·`body`(본문만) 모드가 있지만 선택 UI가 없다.

**웹 대비 빠진 것**

- 챕터 단위 복사(웹 `JournalChapterItem.vue`), 꿈 섹션 단위 복사.
- 해석 포함 범위 선택(전체 / 보류 제외 / 본문만).
- TXT 파일 내보내기. 웹과 서버의 TXT 내보내기 API(챕터 `GET /api/journal/chapter/{id}/export`, 엔트리 `GET /api/journal/entries/export`, 스레드 `GET /api/journal/threads/{id}/export?includeReflection`)는 아직 쓰지 않는다. 공유 시트의 "파일로 저장" 대상이 대신할 수 있지만 파일 형식은 보장하지 않는다.

복사·공유는 서버 데이터를 바꾸지 않으므로 조회 전용 계약(§8)과 충돌하지 않는다.

### 4.9 스레드 글 목록 (구현·미검증)

`ThreadResultScreen`(헤더 `스레드 글 목록`)은 웹 스레드 상세(`JournalThreadDetailContent.vue`, 모달·독립 페이지 공용)의 읽기 부분을 스택 화면으로 옮긴 것이다. 웹에서 기간 스레드 요약이나 스레드 칩을 누르면 스레드 상세가 열리는 것과 같은 자리다.

**진입**

- 기간 스레드 섹션 칩(§5.9), 엔트리 카드·엔트리 상세의 스레드 칩(§5.8, §4.5)에서 `openThreadResult`로 연다. 파라미터는 `{ threadId, title }`이고 `title`은 스레드 정보를 받기 전 임시 제목이다.

**조회** (두 요청을 함께 보낸다)

| 대상 | 요청 | 쓰는 필드 |
|---|---|---|
| 스레드 정보 | `GET /api/journal/threads/{id}` → `rsltObj: JournalThreadDto` (`getJournalThread`) | `title`, `prefix`(`name`, `textClass`), `lifecycle.lifecycleKey`, `firstEntryDate`·`lastEntryDate`(소속 기간), `membershipCount`, `markdownContent`/`content`(본문), `tag.list`(소속 엔트리 태그 집계) |
| 소속 엔트리 | `GET /api/journal/threads/{id}/entries` → `rsltList: JournalEntryDto[]` (`getJournalThreadEntries`) | 엔트리 전체 필드(`stdrdDt`, `contentType`, `title`, `content`, `sortOrder`, `tag`, `lifecycle`, `reflectionList` 등). 연관 스레드 합성(`relatedThreadIds`)은 쓰지 않는다 |

- 소속 엔트리 응답은 서버가 일자 → 챕터 `sortOrder` → 엔트리 `sortOrder` → ID 오름차순으로 정렬하고(`JournalThreadEntryService.getEntriesByThread`), 해석(`reflectionList`)·라이프사이클을 일자 조회와 같은 계약으로 채운다. `threadList`는 비어 온다.
- 스레드 정보 조회만 실패하면 헤더를 임시 제목으로 두고 목록은 표시한다(경고 로그). 소속 엔트리 조회가 실패하면 오류 문구와 `다시 시도`를 표시한다. 401은 오류 로그를 남기지 않는다. 늦게 도착한 응답은 버린다.

**화면**

- 스레드 카드: `🧵 스레드` + 말머리 배지(있을 때, `textClass` 색 글자·테두리) + 라이프사이클 배지(`진행 중`/`보류`/`완료`, 값이 없으면 `진행 중`) / 제목 / `{소속 기간} · 소속 엔트리 N건`(기간은 같은 날이면 하루, 아니면 `first ~ last` — 웹 `formatThreadMembershipPeriod`) / 본문(HTML → 텍스트, 길면 6줄로 접고 `더보기 ▾`) / `소속 엔트리 태그` 칩(표시 전용 — 집계 태그는 일기·꿈 구분이 없어 태그별 기록 종류를 정할 수 없음).
- 목록 머리: 복사·공유 바(`이 스레드 글`, §4.8), `N일 · M건`, 정렬 토글 `최신순`(기본)·`오래된순`(웹 스레드 상세 순서).
- 날짜별 묶음: 날짜 헤더 `YYYY-MM-DD (요일)` + `이 날 보기 ›`(누르면 오늘 탭 일 모드로 그 날짜, `navigateToDailyHub`). 같은 날짜 안은 서버 순서를 유지한다. 날짜 없는 엔트리는 맨 뒤 `날짜 없음` 묶음.
- 엔트리 카드: `일기`/`꿈`/`노트`/`해석` + `#순번`, 라이프사이클 `보류`·`완료` 배지(진행 중은 생략), 제목(있을 때 한 줄), 본문 미리보기(3줄, 140자), 엔트리 태그 칩(누르면 태그별 기록). 꿈은 꿈 색이다.
- 엔트리를 누르면 상세 읽기를 push한다(`{ entry, isDream, loadThreads: true }`, `dayTags` 없음, §4.5).
- 빈 결과: `이 스레드에 소속된 엔트리가 없습니다.`(웹 문구). 당겨서 새로고침을 지원한다.
- 읽기 전용: 라이프사이클 변경, 소속 추가·해제, 연관 스레드 표시·합성, 수정·삭제·댓글, 서버 TXT 내보내기는 두지 않는다(§1.2).
- 저널 스레드 목록(§4.11)에서 스레드를 눌러도 이 화면이 열린다.

### 4.10 햄버거 메뉴 (구현·미검증)

웹 사이드바의 **사용자 메뉴 전체**를 모바일에서 여는 왼쪽 드로어다. 관리자(`관리자`, `mode=MNGR`) 메뉴는 넣지 않는다.

**메뉴 출처 (웹과 같은 SSOT)**

- 웹 사이드바는 DB `menu` 테이블을 `GET /api/menus?mode=USER`(`MenuRestController`)로 받아(`frontend-vue` `shared/menu/stores/menu.ts`) 트리로 그린다(`SidebarMenuItem.vue`). 모바일도 같은 요청(`getUserMenus`)을 쓰므로 메뉴 추가·이름 변경·순서 변경·게시판 추가가 앱 수정 없이 반영된다. 서버가 사용 중·사이드바 표시 메뉴만 주고, `BOARD` 펼침 메뉴(일반게시판) 아래에 게시판을 주입하고, 권한으로 거른다. 모바일은 `mode=MNGR`을 요청하지 않는다.
- 2026-10-06 DB 기준 사용자 메뉴(정렬 순):

| 묶음 | 메뉴 (웹 URL) | 모바일 동작 |
|---|---|---|
| 저널 | 저널 일자 (`/app/journal/day/home`) | 오늘 탭으로 이동 (구현) |
| 저널 | 저널 스레드 (`/app/journal/thread/list.do`) | 저널 스레드 목록 §4.11 (구현) |
| 저널 | 저널 결산 (`/app/journal/annual/list.do`) | 저널 결산 목록 → 상세 §4.12 (구현) |
| Keep | Keep 전수관리 (`/keep`) | Keep 목록 §4.14 → 상세 §4.15 (구현, 읽기 전용) |
| 일반게시판 | 서버가 주입한 게시판들(현재 `1`) | 준비 중 §4.13 |
| 일정 | 일정 달력 (`/app/schedule/calendar.do`) | 준비 중 §4.13 |
| (사용자) | 내 정보 (`/app/user/my/page.do`) | 웹 사이드바 숨김(`sidebar_visible_yn=N`)이라 표시하지 않는다. 나 탭이 같은 역할이다 |

- 최상위 `MAIN` 노드(`사용자`)는 컨테이너라 그 자식들을 묶음(섹션)으로 편다. 묶음 아래 메뉴는 한 단계로 평탄화하고, 묶음 없이 바로 달린 메뉴는 이웃끼리 이름 없는 묶음으로 모은다. 하위 메뉴가 없는 묶음(게시판이 없는 일반게시판 등)도 `표시할 메뉴가 없습니다.`로 남긴다. `useYn=N`·`sidebarVisibleYn=N`·이름 없는 메뉴는 버린다.
- URL → 화면 매핑은 `src/navigation/appMenu.ts`의 `resolveMenuTarget`이 한다(쿼리·끝 `/` 무시). 매핑이 없는 URL은 모두 준비 중 화면으로 간다. 그래서 웹에 새 메뉴가 생기면 드로어에는 바로 나타나고 `준비 중`으로 열린다.
- 메뉴 조회 결과는 5분 캐시하고 동시 요청은 하나로 합친다. 조회가 실패하거나 빈 목록이면 웹 메뉴를 본뜬 기본 메뉴(`FALLBACK_USER_MENU`, 위 표와 같음·게시판 없음)를 쓰고 드로어 아래에 `서버 메뉴를 불러오지 못해 기본 메뉴를 보여줍니다.`를 표시한다. 기본 메뉴는 캐시하지 않아 다음에 열 때 다시 조회한다.

**화면**

- `☰`: 오늘·검색·나 탭 헤더의 `DreamDiary` 왼쪽, 메뉴 화면 헤더의 `‹` 오른쪽(§4.1). 의존성 추가 없이 RN `Modal` + `Animated`로 만든 사이드 시트다(`@react-navigation/drawer` 미사용).
- 드로어: 왼쪽에서 밀려 나오는 패널(너비 `min(320, 화면 82%)`, 열기 220ms·닫기 180ms) + 반투명 배경. 머리 `DreamDiary` / `메뉴` / `✕`. 묶음 제목 아래 메뉴 항목. 앱에 화면이 없는 메뉴는 오른쪽에 `준비 중` 배지.
- 현재 메뉴 강조: 화면이 넘겨 준 웹 URL(`currentUrl`)과 같은 항목에 왼쪽 강조 막대 + 배경 + 굵은 강조색 글씨. 오늘 탭 = `저널 일자`, 스레드 목록 = `저널 스레드`, 결산 목록·상세 = `저널 결산`, Keep 목록 = `Keep 전수관리`(Keep 상세는 `☰` 없는 상세 헤더라 해당 없음), 준비 중 = 그 메뉴. 검색 탭과 나 탭은 웹 사용자 메뉴에 대응 항목이 없어(내 정보는 숨김) 강조하지 않는다.
- 닫기: 배경 탭, `✕`, Android 뒤로 가기(드로어만 닫고 화면은 그대로), 항목 선택. 현재 메뉴를 고르면 닫기만 한다.
- 이동: `저널 일자`는 `Main`으로 돌아가 오늘 탭을 연다(위에 쌓인 메뉴 화면은 닫힘). 나머지는 §4의 `pop: true` 규칙을 따른다. 하단 탭 바와 탭 스타일은 바꾸지 않는다. 메뉴 화면은 스택 화면이라 탭 바가 보이지 않는다(상세 읽기와 같음).

### 4.11 저널 스레드 목록 (구현·미검증)

`ThreadListScreen`(헤더 `저널 스레드`)은 웹 스레드 목록(`/app/journal/thread/list.do`, `journalThreadList.fetchList`)의 읽기 부분이다.

- 조회: `GET /api/journal/threads?page=&size=20`(`getJournalThreadPage`) → `rsltObj: Page<JournalThreadDto>`. 정렬은 서버 순서(소속 엔트리 최신 날짜 기준)를 그대로 쓴다. 끝까지 스크롤하면 다음 페이지를 이어 붙인다(이미 받은 ID는 버림). 당겨서 새로고침은 첫 페이지부터 다시 받는다.
- 제목 검색: 검색어를 입력하고 `검색` 버튼·키보드 검색 키를 눌러야 검색한다(`searchType=title&searchKeyword=`). 입력만으로는 요청하지 않는다(검색 탭과 같은 원칙). `✕`는 입력을 지우고, 검색어가 적용된 상태였다면 전체 목록을 다시 받는다.
- 요약 줄: `전체 N개` 또는 `"검색어" N개`(`totalElements`).
- 스레드 행: 말머리 배지(`textClass` 색) + 라이프사이클 배지(`진행 중`/`보류`/`완료`, 값이 없으면 `진행 중`, 스레드 글 목록과 같은 `LIFECYCLE_META`) / `🧵 제목` / `{소속 기간} · 소속 엔트리 N건` / 소속 엔트리 태그 최대 6개(표시 전용). 누르면 스레드 글 목록(§4.9)을 연다.
- 상태: 첫 조회 중 표시, 빈 결과(`스레드가 없습니다.` / 검색 결과 없음), 실패 시 오류 문구 + `다시 시도`, 다음 페이지 실패는 목록 끝의 `다시 시도`. 늦게 도착한 응답은 버린다.
- 웹 대비 없는 것: 말머리 탭, 라이프사이클 필터, 등록·수정·삭제·라이프사이클 변경(§1.2).

### 4.12 저널 결산 (구현·미검증)

웹 결산 목록·상세(`/app/journal/annual/list.do`, `journalAnnual`)의 읽기 부분이다.

- 결산 목록 `AnnualListScreen`(헤더 `저널 결산`): `GET /api/journal/annuals`(연도별 `JournalAnnualDto` 목록)와 `GET /api/journal/annual/total`(전체 꿈 기록 집계)을 함께 보낸다. 위에 `총 꿈 기록 N일 / M회` 카드, 아래 연도 카드(`📅 {제목 또는 YYYY년 결산}`, `상세 ›`, `꿈 N일 / M회`, 꿈 기록 완료(`dreamComptYn=Y`)면 `🌙✓ 완료`, 본문 4줄 미리보기, 결산 태그 칩(표시 전용)). 카드를 누르면 결산 상세를 연다. 집계만 실패하면 카드 값을 `-`로 둔다.
- 결산 상세 `AnnualDetailScreen`(헤더 = 결산 제목): `GET /api/journal/annual/{yy}`. `요약` 카드(꿈 집계, 완료 표시, 본문 전체 — HTML → 텍스트, 태그 칩) + `리뷰 N`(리뷰마다 제목·본문 카드) + 안내 `일기 결산·꿈 결산(연도별 목록·태그 집계)은 웹에서 볼 수 있습니다.`
- 두 화면 모두 당겨서 새로고침, 실패 시 오류 문구 + `다시 시도`, 빈 목록 `결산 데이터가 없습니다.`.
- 웹 대비 없는 것: 결산 등록·수정·삭제, 리뷰 작성, 일기 결산·꿈 결산 탭(연도별 엔트리 목록·태그 집계).

### 4.13 준비 중 화면

`MenuPlaceholderScreen`(헤더 = 메뉴 이름)은 모바일 화면이 없는 사용자 메뉴의 공용 화면이다.

- 내용: `🚧` 카드에 `{묶음} › {메뉴}`, `모바일 앱에서는 준비 중입니다`, `이 메뉴는 이후 모바일 버전에서 제공할 예정입니다. 지금은 웹에서 이용해 주세요.`
- 서버 요청을 하지 않는다. 대상: 일반게시판의 게시판들, 일정 달력, 그리고 앞으로 웹에 추가될 매핑 없는 사용자 메뉴. Keep 전수관리는 2-0부터 Keep 목록(§4.14)을 연다.

### 4.14 Keep 전수관리 — 목록 (구현·미검증, 2-0 읽기 전용)

`KeepHomeScreen`(헤더 `Keep 전수관리`, `☰` 강조 = `Keep 전수관리`)은 웹 `Keep 전수관리`(`/keep`, `frontend-vue` `KeepPage.vue`)의 읽기 부분이다. 계획·웹 분석·API는 [`keep-todo-plan.md`](./keep-todo-plan.md)를 따른다.

- 조회: `getKeepList`(`GET /api/prospective/keeps?scope=all`, 페이지 없음, lifecycle 포함) + `getKeepProjects` + `getKeepTags` + `getKeepPrefixOptions`를 함께 보낸다. 목록이 실패하면 오류 문구 + `다시 시도`. 보조 목록 실패는 목록을 막지 않는다 — Project 실패는 칩 줄에 `Project 목록을 불러오지 못했습니다. 당겨서 다시 시도하세요.`, 태그·말머리 실패는 목록에 붙은 값으로 선택지를 만들고 필터 시트에 안내. 읽기 응답이 HTTP 200 + `rslt=false`면 서버 `message`로 오류 처리한다. 첫 진입 후 화면에 돌아올 때마다 조용히 다시 받고(목록 유지), 당겨서 새로고침. 늦게 도착한 응답은 버린다. 401은 공통 처리(§7.3)로 로그인 화면에 가며 화면 오류를 띄우지 않는다.
- 목록 위(스크롤과 함께 움직임), 위에서부터:
  - Project 칩(가로 스크롤): `전체`(기본) · `미지정` · OPEN Project(서버 순서). 고른 Project가 새로고침 후 OPEN 목록에 없으면 `전체`로 돌아간다.
  - 보기 탭: `진행 N` · `기한 N` · `종결 N`(Project 범위와 필터를 적용한 건수).
    - 진행: 진행 중(OPEN·보류, 웹과 같이 보류도 진행 쪽). 웹 정렬과 같게 기한 오름차순, 기한 없는 항목은 아래에 서버 순서(`sortOrder` → `id`).
    - 기한: 진행 중이면서 기한(`expireDt`)이 있는 항목을 `지남 / 오늘 / 7일 이내 / 그 이후` 묶음으로(묶음 머리 + 건수, 묶음 안 기한 오름차순).
    - 종결: 완료·실패·만료·내려놓음(서버 순서).
  - 검색줄: 제목·본문 부분 일치(대소문자 무시). `검색` 버튼·키보드 검색 키로만 적용(검색 탭과 같은 원칙), `✕`는 입력과 적용된 검색어를 지운다. 오른쪽 `필터`(걸린 조건 수 표시)가 필터 시트를 연다.
  - 필터 시트 `KeepFilterSheet`(아래에서 올라오는 시트): `조건`(`기한 지남` = 진행 중 + 기한이 오늘 이전, `★ 중요`), `말머리`(`전체` + 말머리), `태그`(`전체` + 목록에 실제로 붙은 태그와 건수, 서버 태그 순서). 같은 칩을 다시 누르면 해제, `모두 해제`·`완료`. 모든 조건은 AND(웹 `filtered`와 같음).
  - 걸린 조건 칩(`"검색어"` · `기한 지남` · `★ 중요` · `[말머리]` · `#태그`, 누르면 그 조건 해제) + `초기화`.
  - 복사·공유 바 `JournalCopyShareBar`(`{보기} N건`, §4.8). 결과가 있을 때만.
- 행(누르면 Keep 상세):
  - 첫 줄: 종결 아이콘(✓ ✕ ⌛ ⊘) · `★`(중요) · `[말머리]`(웹과 같은 `#287D94` 굵게) · 제목(중요면 굵게, 종결이면 흐리게) · 배지(`보류` 노랑 / 종결 라이프사이클 색 배지 완료 초록·실패 빨강·만료 노랑·내려놓음 회색 / `요구`).
  - 둘째 줄: `기한 ~MM/DD · D-n`(다른 해는 `~YY/MM/DD`; 진행 중 지난 기한은 경고색 `N일 지남`, 오늘은 강조색 `오늘`; 종결은 날짜만) · `일시 {dateText}` · `📁 Project`(`전체` 범위에서만, 미지정은 생략) · 등록 `YYYY.MM`.
  - 태그 칩 `#[카테고리]이름`(일기 태그와 같은 색). 누르면 태그 필터를 걸거나 푼다(태그별 기록 화면으로 가지 않음).
  - 레거시 `COLLAPSED` 상태는 무시한다. 완료 체크박스·스와이프·길게 누르기·`+` 버튼은 없다(2-0 읽기 전용).
- 빈 상태: 조건이 걸렸거나 Project 범위가 `전체`가 아니면 `조건에 맞는 Keep이 없습니다.`, 아니면 보기별 문구(`진행 중인 Keep이 없습니다.` / `기한이 있는 진행 중 Keep이 없습니다.` / `종결된 Keep이 없습니다.`). 목록 끝 안내 `모바일 Keep은 읽기 전용입니다. 등록·완료·수정은 웹 Keep 전수관리에서 합니다.`
- 웹 대비 없는 것: 빠른 추가, 완료 체크·라이프사이클 변경, 중요·요구 토글, 편집·삭제, 정렬 순서 변경, Project 관리, 접기(COLLAPSED)(2-1 이후, `keep-todo-plan.md` §5).

### 4.15 Keep 상세 (구현·미검증, 2-0 읽기 전용)

`KeepDetailScreen`(헤더 `‹ 뒤로` · `Keep` 배지 · `복사` · `공유`)은 Keep 1건을 읽기 전용으로 보여 준다.

- 조회: `getKeepDetail`(`GET /api/prospective/keep/{id}`, 소유자 확인). 받기 전에는 목록에서 넘긴 항목을 그대로 보여 준다. **상세 응답에는 lifecycle이 없다**(백엔드가 목록에서만 붙임) — 라이프사이클은 목록 항목 값을 쓰고, 목록 항목 없이 열렸거나 당겨서 새로고침하면 `getKeepList`·`getKeepProjects`도 다시 받아 라이프사이클과 Project 이름을 채운다. 상태·태그가 상세에 비어 있으면 목록 값을 쓴다.
- 내용: 라이프사이클 배지(진행 중·보류·종결 색) + `★ 중요`·`요구` 배지 / `[말머리]` + 제목 / 필드 상자 — `기한`(없음 또는 `YYYY-MM-DD` + D-day, 지난 기한 경고색), `일시`, `위치`, `Project`(없으면 `미지정`), `말머리`, `태그`(칩, 표시 전용), `등록`(`YYYY.MM.DD HH:mm`), `수정`(등록과 다를 때) / `내용` — 마크다운을 읽기 쉬운 평문으로(제목·강조 기호 제거, 목록 `•`, 체크 `☑`/`☐`, 인용 `│`, 링크 `글 (url)`, 이미지 `[이미지: 설명]`, HTML이면 저널과 같은 HTML → 텍스트). 본문은 길게 눌러 선택할 수 있다. 본문이 없으면 `(내용 없음)`. 웹에는 별도 상세 화면이 없어(제목 클릭 = 수정 모달) 수정 모달의 필드를 읽기 형태로 보여 준다.
- 상태: 첫 조회 중 표시, 실패 시 오류 상자 + `다시 시도`(목록에서 넘긴 항목이 있으면 그 내용은 계속 보임), 당겨서 새로고침. 다른 사용자의 ID·삭제된 Keep은 서버 오류 문구를 보여 준다.
- 끝 안내: `읽기 전용입니다. 완료·수정은 웹 Keep 전수관리에서 합니다.` 편집·삭제·라이프사이클 버튼은 없다.

## 5. 날짜 조회 계약

### 5.1 공통

- 토글: `일 | 주 | 월`. 앱 진입 시 일 모드로 시작한다.
- 모드를 바꾸면 현재 선택 일자를 기준으로 그 날짜가 속한 주(월요일 시작) 또는 달을 연다.
- 탐색 행은 `‹ 기간 라벨 ›` 형태다. ‹ ›는 하루·한 주·한 달씩 이동하며, 현재 기간(오늘·이번 주·이번 달)에서는 › 를 비활성화한다. 미래 날짜·주·달로는 이동하지 않는다.
- 기간 라벨 옆에 `▾`를 표시하고, 라벨을 누르면 날짜 선택 피커가 열린다(§5.6).
- 현재 기간이 아니면 라벨 아래에 `오늘로` / `이번 주로` / `이번 달로` 작은 버튼을 별도로 표시하며, 누르면 현재 기간으로 돌아간다. 라벨 자체는 더 이상 현재 기간 이동 동작을 갖지 않는다.
- 당겨서 새로고침을 지원한다. 조회 실패는 오류 문구로 표시하며, 주·월 보기는 `다시 시도` 버튼을 제공한다.
- 화면 배치는 `탐색 행(기간 라벨) → 기간 태그 클라우드 패널(§5.7) → 기간 스레드 섹션(§5.9) → 복사·공유 바(§4.8) → 일자·엔트리 목록` 순서다.
- 일·주·월 조회 요청에는 웹 기본값과 같은 `showDiaries=true&showDreams=true`를 함께 보낸다(§6.2).

### 5.2 일별 조회 (기본 보기)

- 요청: `GET /api/journal/days?viewType=DAILY&stdrdDt=YYYY-MM-DD&showDiaries=true&showDreams=true`
- 기준일 하루에 속한 저널 일자와 엔트리를 표시한다. 챕터(서버 정렬 순서)를 먼저 표시하고, 이어서 꿈 섹션 엔트리를 표시한다.
- 챕터와 엔트리의 서버 정렬 순서를 유지한다.
- 엔트리 카드에는 엔트리 태그와 소속 스레드 칩을 표시한다(§5.8). 일 보기에는 일자 헤더가 없으므로 일자 태그는 기간 태그 클라우드 패널의 `일자 태그` 행으로만 보인다.
- 빈 상태 문구: 오늘이면 `오늘은 아직 기록이 없습니다.`, 그 외 날짜는 `이 날의 기록이 없습니다.`
- 선택한 엔트리는 상세 읽기로 이어진다.

### 5.3 주별 조회

- 요청: `GET /api/journal/days?viewType=WEEKLY&weekStartDt=YYYY-MM-DD&showDiaries=true&showDreams=true` (월요일)
- 한 주는 월요일부터 일요일까지의 7일이다. 기간 라벨은 `YYYY.MM.DD – YYYY.MM.DD`이다.
- 서버가 반환한 일자를 **최신 날짜부터(내림차순)** 표시하며, 각 일자는 날짜·요일 헤더, 그 아래 일자 태그 칩, 그날의 챕터·엔트리 순서로 보여준다. 반환된 일자에 엔트리가 없으면 `기록 없음`으로 구분한다.
- 결과가 없으면 `이번 주 기록이 없습니다.`를 표시하고, 조회 실패와 구분한다.
- 선택한 엔트리는 상세 읽기로 이어진다.

### 5.4 월별 조회

- 요청: `GET /api/journal/days?viewType=LIST&yy=YYYY&mnth=M&showDiaries=true&showDreams=true`. 서버에는 `MONTHLY` 보기 유형이 없으므로 웹 월간 화면과 같이 `LIST`를 사용한다(§6.2).
- 기준 연·월에 속한 저널 일자 중 **엔트리가 있는 일자만** 최신 날짜부터(내림차순) 연속 목록으로 표시한다. 일자 섹션 구성(날짜·요일 헤더, 일자 태그 칩, 챕터·엔트리)은 주별과 같다. 기간 라벨은 `YYYY년 M월`이다.
- 기준 연·월을 이전/다음 달로 이동하며 조회하고, 미래 달로는 이동하지 않는다.
- 기록이 없는 달(`이 달의 기록이 없습니다.`)과 조회 실패 상태를 구분한다.
- 선택한 엔트리는 상세 읽기로 이어진다.

### 5.5 정렬 기준

- 백엔드 `JournalDaySearchParam.sort`의 기본값은 `ASC`이고, 웹은 `journal_day_sort`(기본 `DESC`)에 따라 프런트에서 순서를 뒤집는다.
- 모바일은 웹 기본값과 같이 주·월 목록의 일자를 `stdrdDt` **내림차순**으로 정렬한다. 정렬 전환 UI는 없다.
- 일자 안의 챕터·엔트리 순서는 서버 순서를 유지한다.

### 5.6 날짜 선택 피커

`JournalDatePickerModal`(외부 라이브러리 없이 구현한 바텀시트 모달)이 일·주·월 보기의 기간 라벨에서 열린다. 배경을 누르거나, Android 뒤로 가기를 누르거나, `닫기`를 누르면 닫힌다.

| 보기 | `mode` | 처음 여는 패널 | 선택 결과 |
|---|---|---|---|
| 일 | `day` | 날짜 그리드 (일~토 열) | 누른 날짜 |
| 주 | `week` | 날짜 그리드 (월~일 열) | 누른 날짜가 속한 주의 월요일 |
| 월 | `month` | 연·월 그리드 (12개월) | 누른 연·월 |

**헤더**

- 왼쪽에 캡션 `날짜 선택` / `주 선택` / `월 선택`을 표시한다.
- 오른쪽에 `오늘` / `이번 주` / `이번 달` 버튼과 `닫기` 버튼을 둔다. 현재 기간 버튼은 오늘·이번 주·이번 달을 선택하고 피커를 닫는다.
- 선택하면 즉시 피커를 닫고, 해당 보기가 그 기간을 조회한다.

**탐색 행 `‹ 제목 ›`**

| 패널 | 제목 | ‹ › | 제목을 누르면 |
|---|---|---|---|
| 날짜 그리드 | `YYYY년 M월 ▾` | 한 달 이동 | 연·월 패널로 올라간다 |
| 연·월 (12개월) | `YYYY년 ▾` | 한 해 이동 | 연도 패널로 올라간다 |
| 연도 (12년) | `YYYY – YYYY` | 12년 이동 | 연·월 패널로 돌아간다 |

- 연도 패널은 마지막 페이지가 올해로 끝나도록 12년 단위로 나누며, 1900년까지 거슬러 갈 수 있다.
- 일·주 모드에서는 연도 → 연·월 → 날짜 그리드 순서로 내려오며 고른다. 월 모드는 연·월 패널에서 바로 선택한다.

**날짜 그리드**

- 항상 6주(42칸) 고정이며, 앞뒤 달의 날짜는 흐리게 표시한다. 앞뒤 달 날짜도 미래가 아니면 선택할 수 있다.
- 일요일·토요일 숫자 색을 구분한다.
- 일 모드의 선택일은 채운 원, 오늘은 테두리 원(링)으로 표시한다.
- 주 모드는 선택한 주의 행 전체를 띠로 강조한다. 띠 안의 오늘 링은 밝은 색으로 바꾼다.

**미래 비활성**

- 오늘 이후 날짜, 이번 달 이후 월, 올해 이후 연도는 비활성으로 흐리게 표시하고 누를 수 없다.
- 보기 쪽에서도 선택값을 현재 기간 이하로 한 번 더 제한한다.

**기록 점**

- 날짜 그리드에서 표시 중인 달을 월 API(`getMonthlyJournalDays`, `viewType=LIST&yy&mnth`)로 조회하고, 엔트리가 있는 날(`dayHasEntries`) 아래에 점을 찍는다.
- 조회한 달은 피커 컴포넌트 상태에 달 단위로 캐시한다. 피커를 열 때마다 현재 값이 속한 달은 다시 조회해 최신으로 맞춘다.
- 하단에 상태를 표시한다: 조회 중 `기록 표시를 불러오는 중…`, 실패 시 `기록 표시를 불러오지 못했습니다 · 다시 시도`, 평소에는 `기록이 있는 날` 범례.
- 연·월 패널은 이미 캐시된 달에만 점을 찍는다. 월 모드는 날짜 그리드를 거치지 않으므로 현재 구현에서는 연·월 패널에 점이 표시되지 않는다.

### 5.7 기간 태그 클라우드 패널

`JournalPeriodTagCloudPanel`은 웹 `JournalTagCloudHeader.vue`의 일자·일기·꿈 3행 태그 클라우드를 옮긴 접이식 패널이다. 일·주·월 보기가 각자 탐색 행 바로 아래에 렌더한다.

| 보기 | 헤더 문구 | 기간 파라미터 |
|---|---|---|
| 일 | `이 날의 태그` | `stdrdDt=YYYY-MM-DD` |
| 주 | `이 주의 태그` | `weekStartDt=YYYY-MM-DD` (월요일) |
| 월 | `이 달의 태그` | `yy=YYYY&mnth=M` |

**데이터**

- 세 행을 동시에 조회한다: `일자 태그`는 `GET /api/journal/day/tags?(기간)`, `일기 태그`·`꿈 태그`는 `GET /api/journal/entry/tags?(기간)&type=DIARY|DREAM`.
- 기간 파라미터는 위 표 중 하나만 보낸다. 백엔드(`TagSearchParam`)는 좁은 기간을 우선한다(`stdrdDt` > `weekStartDt` > `yy`+`mnth`).
- 각 태그는 `[카테고리]`(있을 때) + 이름 + 건수(`contentSize`)로 표시한다. 순서는 서버 순서를 따른다.

**크기·색** (`journalTagStyle.ts`)

- 크기는 서버가 정한 `tagClass`(`ts-1`~`ts-9`)를 따른다. 웹의 0.9em~2.7em을 폰 폭에 맞춰 12~24pt로 압축했고, `ts-9`는 굵게 표시한다. `tagClass`가 없거나 형식이 다르면 `ts-1`로 본다.
- 색은 `textClass`(태그 프로필 색, 예: `text-primary`, `text-noti`)가 알려진 클래스면 그 색을 우선하고, 없으면 웹 `tag.scss`의 크기 단계별 색을 쓴다.
- 카테고리와 건수는 웹 `noti` 색(`#ED7000`)의 작은 글씨로 표시한다.

**접힘·펼침**

- 헤더를 누르면 접히고 펼쳐진다. 펼침이 기본이다.
- 펼침 상태는 모듈 변수로 기억해 일·주·월 보기가 공유한다. 보기를 바꿔 패널이 다시 마운트돼도 마지막 상태를 이어받으며, 앱을 다시 시작하면 펼침으로 돌아간다(저장소에 저장하지 않음).
- 헤더 보조 문구: 조회 중 `불러오는 중…`, 태그가 없으면 `태그 없음`, 전부 실패하고 태그가 없으면 `불러오지 못했습니다`. 태그가 있으면 펼침 상태에서는 `N개`(세 행 합계), 접힘 상태에서는 건수 상위 4개 태그를 `#이름`으로 이어 보여준다.
- 본문은 펼침 상태이고 조회가 끝났으며 태그가 하나 이상 있거나 오류가 있을 때만 표시한다.

**행별 표시**

- 각 행은 처음 **18개**까지만 보여주고, 넘치면 `+N 더보기`를 표시한다. 누르면 그 행 전체를 펼친다. 펼친 행은 기간이 바뀌면 다시 18개로 돌아간다.
- 태그가 없는 행은 `-`, 조회에 실패한 행은 `불러오지 못했습니다`를 표시한다. 세 요청은 서로 독립이라 한 행이 실패해도 다른 행은 표시한다.
- 하나라도 실패하면 본문 아래 `다시 시도`로 세 행을 다시 조회한다.

**다시 불러오기**

- 기간이 바뀌면(날짜 이동, 피커 선택, 보기 전환) 로딩 상태로 바꾸고 세 행을 새로 조회한다.
- 같은 기간에서 화면에 다시 돌아오면(탭 포커스) 로딩 표시 없이 조용히 갱신한다.
- 늦게 도착한 이전 기간의 응답은 버린다.
- 목록의 당겨서 새로고침은 패널을 다시 조회하지 않는다.
- 401은 오류 로그 없이 전역 자동 로그아웃 흐름을 따른다(§7.3).

**동작 범위**

- 태그를 누르면 태그별 기록 화면을 연다(§4.4.2). 종류는 행이 정한다(`일자 태그` → `day`, `일기 태그` → `diary`, `꿈 태그` → `dream`).
- 기간 스레드는 패널 안이 아니라 패널 아래 별도 섹션으로 둔다(§5.9).

### 5.8 태그·스레드 칩

`JournalTagChips.tsx`는 웹 `TagChip.vue`의 인라인 태그 표기를 칩으로 옮긴다. 태그 칩을 누르면 태그별 기록 화면을 연다(§4.4.2, 종류는 칩 종류). 카드(누르면 상세) 안에 있어도 칩 누름이 우선한다. `pressable={false}`로 표시 전용으로 쓸 수 있으며, 스레드 글 목록의 소속 엔트리 태그 집계가 그렇게 쓴다. 스레드 칩(`JournalThreadChips`)을 누르면 그 스레드의 글 목록(§4.9)을 연다. 스레드 칩도 같은 `pressable` 옵션이 있고 기본은 누를 수 있음이다.

| 칩 | 데이터 | 위치 | 표기 |
|---|---|---|---|
| 엔트리 태그 | `entry.tag.list` | 일·주·월 보기의 모든 일기·꿈 엔트리 카드(챕터 엔트리와 꿈 섹션 엔트리) 하단 | `#[카테고리]태그명`. 꿈 엔트리는 꿈 색 칩, 그 외는 일기 색 칩 |
| 소속 스레드 | `entry.threadList` | 엔트리 태그 아래 | `🧵 스레드 제목`. 같은 `threadId`는 한 번만, 제목이 빈 항목은 생략 |
| 일자 태그 | `day.tag.list` | 주·월 보기 각 일자의 날짜·요일 헤더 바로 아래 | `#[카테고리]태그명`, 일자 색 칩 |

- 태그 목록은 `displayTagsOf`로 정규화한다. 이름은 `name`을 우선하고 없으면 `tag.name`을 쓰며(백엔드 `TagContentDto.resolveDisplayName`과 같은 규칙), 이름이 빈 항목은 버리고, 같은 `tagId`는 한 번만 남기며 서버 순서를 유지한다. 카테고리가 없으면 `[카테고리]`를 생략한다.
- 태그·스레드가 없으면 칩 줄 자체를 그리지 않는다.
- 엔트리 상세 화면(§4.5)과 태그별 기록 결과 카드(§4.4.2)도 같은 칩을 쓴다. 스레드 글 목록 카드(§4.9)는 엔트리 태그 칩만 쓴다(응답에 `threadList`가 없음). 검색 탭 태그 매칭(§4.4.1)도 같은 태그 칩을 쓴다. 키워드 검색 결과 카드에는 칩을 표시하지 않는다.

### 5.9 기간 스레드 섹션 (구현·미검증)

`JournalPeriodThreadPanel`은 기간 태그 클라우드 패널 아래에서 그 기간에 엔트리가 등장한 스레드를 보여주는 접이식 섹션이다. 웹 `JournalPeriodThreadSummary.vue`(태그 클라우드 카드 하단의 기간 스레드 요약)를 옮겼다.

| 보기 | 섹션 제목 | 요청 |
|---|---|---|
| 일 | `이 날의 스레드` | `GET /api/journal/threads/period-summary?viewType=DAILY&stdrdDt=YYYY-MM-DD` |
| 주 | `이 주의 스레드` | `…?viewType=WEEKLY&weekStartDt=YYYY-MM-DD` |
| 월 | `이 달의 스레드` | `…?viewType=LIST&yy=YYYY&mnth=M` |

**칩**

- 응답 `rsltList`의 각 항목(`JournalThreadPeriodSummary`: `threadId`, `title`, `prefix`, `entryCount`, `firstEntryDate`)을 서버 순서대로 칩으로 표시한다. `threadId`가 없는 항목은 버린다. 응답 타입은 API 함수(`getJournalPeriodThreadSummary`)에 따로 선언했고, 공용 `AjaxResponse` 타입에는 여전히 `rsltList`가 없다.
- 칩 형식: `🧵` + 말머리 배지(있을 때, `prefix.textClass` 색 글자와 같은 색 테두리) + 제목(한 줄) + `N건`.
- 월 보기는 10개를 넘으면 처음 10개만 보여주고 `펼치기 (+N) ▾`로 나머지를 펼친다(`접기 ▴`로 되돌림). 일·주 보기는 제한하지 않는다(웹 `MONTHLY_VISIBLE_LIMIT`와 같음). 월간 결과는 서버가 `entryCount` 내림차순으로 준다.
- 칩을 누르면 그 스레드의 글 목록 화면(§4.9)을 연다(`openThreadResult`, 파라미터 `{ threadId, title }`). 웹에서 스레드 상세를 여는 것에 해당한다.

**접힘·펼침과 상태**

- 헤더를 누르면 접히고 펼쳐진다. 펼침이 기본이며, 앱 실행 중 모듈 변수로 기억해 일·주·월 보기가 공유한다. 태그 패널과는 따로 기억한다.
- 헤더 보조 문구: 조회 중 `불러오는 중…`, 실패 `불러오지 못했습니다`(펼침 상태에서 `다시 시도`), 결과 없음 `스레드 없음`, 펼침 상태 `N개`, 접힘 상태 앞 2개 제목 + `외 N개`.
- 웹은 결과가 없으면 영역을 숨기지만 모바일은 헤더를 남기고 `스레드 없음`을 표시한다(태그 패널과 같은 방식).
- 다시 불러오기 규칙은 태그 패널과 같다: 기간이 바뀌면 로딩 상태로 새로 조회하고 펼친 목록을 접으며, 같은 기간에서 화면에 돌아오면 조용히 갱신하고, 늦게 도착한 응답은 버린다. 401은 오류 로그를 남기지 않는다.
- 읽기 전용이며 스레드 소속 변경 등 쓰기 동작은 두지 않는다(§1.2).

### 6.1 모바일이 사용하는 조회 API

### 6.2 `viewType`

- 백엔드 `JournalDayViewType`의 값은 `LIST`, `CAL`, `DAILY`, `WEEKLY`, `ANNUAL`, `SEARCH`다. `MONTHLY`는 없다.
- 예전 월별 요청 `viewType=MONTHLY&stdrdDt=YYYY-MM-01`은 사용하지 않는다. 월별은 `LIST&yy&mnth`다.
- `DAILY`는 `stdrdDt`, `WEEKLY`는 `weekStartDt`(월요일), `LIST`는 `yy`·`mnth`, `SEARCH`는 `tagId`·`yy`를 사용한다.
- `DAILY`·`WEEKLY`·`LIST` 요청에는 `showDiaries=true&showDreams=true`(`JOURNAL_DAY_SHOW_FLAGS`)를 붙인다. 웹 기본값과 같으며, 백엔드는 이 값이 참일 때 챕터·일기 엔트리와 꿈 엔트리의 상태·라이프사이클을 반영하고(`JournalDayViewHelper`), `showDiaries`가 참일 때 챕터 요약 태그(`chapter.tag`)를 채운다. 모바일은 챕터 요약 태그를 아직 표시하지 않는다.
- `GET /api/journal/days`(`JournalDayRestController`)는 `LIST`·`CAL`·`DAILY`·`WEEKLY`·`SEARCH`만 분기하며, `ANNUAL`은 `지원하지 않는 일자 보기 타입` 예외로 처리한다. 모바일은 `DAILY`·`WEEKLY`·`LIST`·`SEARCH`만 사용한다.

|---|---|
| 일자 (`JournalDayDto`) | `id`, `stdrdDt`, `tag`(일자 태그), `journalChapterList[]`, `journalDreamSectionList[]` |

| 스레드 소속 엔트리 (`/threads/{id}/entries`의 `rsltList[]`) | 위 엔트리(`JournalEntryDto`)와 같다. 단 `threadList`는 비어 온다 |
| 엔트리 소속 (`JournalThreadEntryDto`, `/entries/{entryId}/threads`의 `rsltList[]`) | `id`, `threadId`, `entryId`, `sortOrder`, `threadTitle`, `entryContentType` |
| 태그 프로필 (`TagProfileDto`, `/tags/{tagId}/profile`의 `rsltObj`) | `content`(태그 설명). 타입에는 `tagId`, `ctgr`, `contentType`, `textClassCd`도 있으나 화면은 `content`만 쓴다 |

- 챕터의 엔트리는 **`journalEntryList` 하나**로 온다. 일기·꿈 구분은 엔트리별 `contentType`(`JOURNAL_DIARY` \| `JOURNAL_DREAM`)으로 한다. 예전 필드 `journalDiaryList`·`journalDreamList`·`journalNoteList`와 `categoryCode`·`categoryName`은 백엔드에 없으므로 사용하지 않는다.
- 꿈은 `journalDreamSectionList[].entries`로 읽는다(`dreamEntriesFromDay`). 백엔드 `JournalDayMapstruct`가 DREAM 챕터의 엔트리를 꿈 섹션으로 옮기고 DREAM 챕터를 `journalChapterList`에서 제거하기 때문이다. 챕터에 남은 `JOURNAL_DREAM` 엔트리는 꿈 스타일로 표시한다.
- 일자에 꿈 섹션 엔트리나 챕터 엔트리가 하나라도 있으면 "엔트리가 있는 일자"로 본다(`dayHasEntries`).

### 6.4 챕터 헤더 라벨

웹 `JournalChapterItem.vue` 헤더와 같은 규칙으로 만든다(`chapterHeaderLabel`).

```text
{타입 라벨} + (요약 챕터면 ": 요약", 아니고 말머리가 있으면 ": {prefix.name}") + (제목이 있으면 " · {title}")
```

- 타입 라벨: `chapterType`이 `DREAM`이면 `꿈`, `NOTE`면 `노트`, 그 외는 `일기`. 웹 메시지 `journal.chapter.type.*`와 같은 값이다.
- 요약 챕터: `summaryYn === "Y"`. 라벨은 웹 `journal.chapter.summary`와 같은 `요약`이다.
- 예: `일기: 요약`, `일기: 업무 · 회의 정리`, `노트 · 메모`, `일기`

### 6.5 이번 달 통계 집계

나 탭은 이번 달 `LIST` 응답에서 다음과 같이 집계한다. 일별 보기와 같은 기준이다.

| 항목 | 집계 |
|---|---|
| 기록 일수 | `dayHasEntries`가 참인 일자 수 |
| 꿈 | 꿈 섹션 엔트리 수 + 챕터 `journalEntryList` 중 `contentType === "JOURNAL_DREAM"` 수 |
| 일기 | 챕터 `journalEntryList` 중 `contentType === "JOURNAL_DIARY"` 수 |

서버가 DREAM 챕터를 꿈 섹션으로 옮기므로 꿈 섹션과 챕터의 꿈 엔트리를 더해도 이중으로 집계되지 않는다.

## 7. 인증·세션 계약

### 7.1 요청 공통 헤더

`src/api/client.ts`의 `request()`는 모든 REST 요청에 다음을 붙인다.

| 헤더 | 값 |
|---|---|
| `Accept` | `application/json` |
| `Content-Type` | `application/json` (`FormData` 전송 시 생략) |
| `Authorization` | SecureStore에 access JWT가 있으면 `Bearer {token}` |
| `X-Client-Channel` | `MOBILE` (항상. 호출 측 `headers`보다 뒤에 병합해 덮어쓸 수 없다) |

- REST 인증의 기준은 쿠키이며, access JWT는 login/refresh 응답의 `Authorization` 헤더에서 저장한다.
- 헤더 상수(`CLIENT_CHANNEL_HEADERS`)는 WebSocket/STOMP 연결을 추가할 때 connect 헤더에도 사용한다. 현재 모바일에는 WebSocket 연결 코드가 없다.

### 7.2 백엔드 채널별 세션 정책

같은 계정으로 웹 세션 1개와 모바일 세션 1개가 공존할 수 있다. 같은 채널에서 두 번째로 로그인할 때만 중복 로그인으로 처리한다.

| 구성 요소 | 현재 구현 |
|---|---|
| `ClientChannel` | `WEB`(기본) / `MOBILE`. `X-Client-Channel` 값이 `MOBILE`(대소문자 무시)일 때만 MOBILE이고, 헤더가 없거나 다른 값이면 WEB이다. 세션 attribute `clientChannel`에 저장한다. |
| `ClientChannelUtils` | 로그인 시점에는 요청 헤더로 채널을 판별해 세션에 저장한다. 로그아웃·세션 만료·동시 세션 제어 시점에는 세션에 저장된 채널을 우선하고, 없으면 헤더를 쓴다. |
| 채널 저장 시점 | JSON 로그인 성공(`AuthRestController`), 폼 로그인 성공(`LoginSuccessHandler`), OAuth2 로그인 성공(`OAuth2AuthenticationSuccessHandler`)에서 저장한다. JWT로 새로 인증된 세션(`JwtAuthenticationFilter`)과 토큰 갱신(`AuthRestController.refreshToken`)은 세션에 채널이 없을 때만 보완한다. |
| `DupIdLoginManager` | 중복 로그인 키를 `채널:아이디`로 관리한다. 추가·제거·중복 확인 모두 채널을 받는다. |
| `AuthenticationHelper` | 중복 로그인 검사를 현재 요청 채널 안에서만 한다. "기존 세션 끊고 로그인" 재시도는 `isDupIdLoginChannel` 세션 attribute로 같은 채널의 재시도만 인정한다. 채널 정보가 없는 기존 세션은 이전 동작을 유지한다. 이 attribute는 `AuthRestController`, `LoginFailureHandler`, `OAuth2AuthenticationFailureHandler`가 기록한다. |
| 로그아웃·세션 종료 | `LogoutHandler`와 `SessionDestroyListener`는 해당 세션 채널의 키만 제거한다. 채널을 알 수 없으면 WEB으로 본다. |
| 최대 세션 | `AuthConfig`가 `ClientChannelSessionRegistry`(세션 ID별 채널 기록, 세션 ID 변경 시 이관, 채널 없으면 WEB)를 등록한다. 중복 로그인 비허용 정책일 때 `WebSecurityAdapter`가 채널당 `maximumSessions(1)`, `maxSessionsPreventsLogin(false)`를 적용하고, 기본 전략을 `ClientChannelConcurrentSessionControlAuthenticationStrategy`로 교체한다. 같은 채널에서 한도를 넘으면 그 채널의 가장 오래된 세션을 만료한다(만료 URL `?dupLoginAt=Y`). 중복 로그인 허용 정책에서는 세션 수 제한이 없다. |
| CORS | `CorsFilter`의 `Access-Control-Allow-Headers`에 `X-Client-Channel`을 추가했다. 브라우저 교차 출처 요청에 필요하며, 네이티브 앱의 `fetch`에는 CORS가 적용되지 않는다. |

채널 분리는 단위 테스트(`ClientChannelUtilsTest`, `DupIdLoginManagerTest`, `AuthenticationHelperDupLoginTest`, `ClientChannelConcurrentSessionControlAuthenticationStrategyTest`, `SessionDestroyListenerTest`)로 검증한다.

### 7.3 인증 상태 확인과 401 처리

| 상황 | 계약 |
|---|---|
| 앱 시작 | `AuthContext`가 SecureStore 토큰을 메모리로 올린 뒤 `GET /api/auth/get-auth-info`를 호출한다. 성공하면 `POST /api/auth/refresh`로 access JWT를 갱신한 다음 사용자를 설정한다. refresh 실패는 경고 로그만 남기고 쿠키 인증을 유지한다. |
| 시작 시 401 | **비로그인 정상 흐름**이다. `get-auth-info`는 `expectedErrorStatuses: [401]`로 호출해 info 로그만 남기고, 저장 토큰을 정리한 뒤 로그인 화면을 표시한다. |
| 시작 시 401 외 오류 | `인증 상태 확인 오류` 화면과 `다시 시도` 버튼을 표시한다. 403은 권한 안내 문구를 쓴다. |
| 로그인 직후 | `POST /api/auth/login` 성공 후 전체 로딩 화면 없이 인증 정보를 다시 확인한다. 사용자를 얻지 못하면 로그인 화면에 실패 문구를 표시한다(§4.2). |
| 요청 중 401 | `client.ts`가 저장된 access 토큰을 지우고 전역 `onUnauthorized` 콜백으로 자동 로그아웃해 로그인 화면으로 전환한다. 401은 `console.info`로만 기록하며, 개발 빌드의 LogBox 오류 토스트를 띄우지 않는다. |
| 화면별 오류 로그 | 조회 훅과 화면(`useJournalDay`·`useJournalWeek`·`useJournalMonth`, 검색·나 탭(검색 태그 매칭 포함), 날짜 선택 피커, 기간 태그 클라우드 패널, 기간 스레드 섹션, 태그별 기록 화면, 스레드 글 목록 화면, 엔트리 상세의 소속 스레드 재조회)은 `isUnauthorizedError(e)`(`ApiError`이고 status 401)이면 `console.error`를 생략한다. 401 외 오류는 지금처럼 `console.error`로 남긴다. |
| 로그아웃 | `POST /api/auth/logout-json` |

## 8. 조회 전용 계약

모바일 v0.1은 저널 데이터에 대해 읽기 요청만 수행한다. 범위 밖 쓰기 기능 목록은 §1.2를 따른다.

- 날짜 조회, 검색, 태그별 기록, 스레드 글 목록과 상세 조회에서 저널 생성·수정·삭제 API를 호출하지 않는다. 태그 설명·스레드 정보도 조회만 하며 편집·삭제·소속 변경은 두지 않는다.
- 햄버거 메뉴와 메뉴 화면(저널 스레드 목록, 저널 결산, 준비 중)도 조회만 한다. 메뉴 조회는 `mode=USER` 읽기 요청이며 메뉴 관리 API는 호출하지 않는다.
- Keep 목록·상세(2-0, §4.14·§4.15)도 조회만 한다. Keep 쓰기 API(완료·라이프사이클·중요/요구 상태·등록·수정·삭제·순서·Project 관리)를 호출하지 않고, 완료 체크박스·스와이프·추가 버튼을 두지 않는다. Keep 쓰기는 2-1부터 단계별로 연다(§1.4).
- 날짜·검색 결과·상세 화면에 저널 생성·수정·삭제 조작을 노출하지 않는다.
- 조회 오류를 해결하기 위해 저널 데이터를 생성하거나 클라이언트 임시 항목을 주입하지 않는다.
- 서버가 반환한 데이터와 오류를 앱 상태의 기준으로 사용한다.
- 복사·공유(§4.8)는 화면에 표시한 데이터를 기기 클립보드나 시스템 공유 시트로 옮길 뿐 서버 데이터를 바꾸지 않으므로 허용한다.

## 9. 공통 화면 상태

모든 조회 화면은 다음 상태를 구분한다.

| 상태 | 계약 |
|---|---|
| 초기 조회 중 | 진행 상태를 표시하고 빈 결과로 단정하지 않는다. |
| 조회 성공 | 현재 조건과 일치하는 서버 확정 데이터를 표시한다. |
| 결과 없음 | 조회가 성공했고 결과가 없음을 안내한다. |
| 조회 실패 | 오류 안내와 재시도 수단을 제공하며 실패를 0건으로 표시하지 않는다. |
| 인증 만료 (401) | 저장된 인증 정보를 정리하고 전역 자동 로그아웃으로 로그인 화면으로 전환한다. 오류 토스트로 표시하지 않는다(§7.3). |

이전 성공 데이터를 유지하는 경우 현재 조회 조건의 데이터인지 구분할 수 있어야 한다. 다른 날짜·기간·검색 조건의 결과를 현재 결과처럼 표시하지 않는다.

## 11. 실기기 확인 체크리스트

`구현·미검증` 항목을 실기기(또는 에뮬레이터 + Expo Go)에서 확인한다. 통과하면 §3 현황을 ✓로 바꾸고, 다르면 해당 절을 실제 동작에 맞춘다.

- [ ] **태그 크기·색 클래스**: 기간 태그 패널에서 서버 `tagClass`(`ts-1`~`ts-9`)에 따라 글자 크기가 단계별로 달라지고, `textClass`가 있는 태그는 그 색으로 표시된다. 웹 같은 기간의 태그 클라우드와 비교한다(§5.7).
- [ ] **`threadList`와 기간 스레드 요약**: 스레드에 속한 엔트리 카드에 `🧵` 칩이 보인다(일·주·월 응답에 `threadList`가 담겨 오는지). `이 날/주/달의 스레드`에 칩·말머리 배지·`N건`이 웹과 같게 나오고, 월 보기에서 10개 초과 시 `펼치기`가 동작한다(§5.9).
- [ ] **태그 설명**: 설명이 있는 태그의 태그별 기록 화면에 설명이 텍스트로 보이고, 없는 태그는 설명 줄 없이 열린다(§4.4.2).
- [ ] **일자 태그 결과의 엔트리**: 일자 태그 결과의 각 날짜 아래에 엔트리가 나온다(`SEARCH` 응답에 챕터·꿈 섹션이 담겨 오는지). 모든 날짜가 `엔트리 없음`이면 응답 구조를 다시 확인한다(§4.4.2).
- [ ] **검색 결과의 엔트리 날짜**: 키워드 검색 결과 카드에 날짜가 보이고, 일기·꿈 태그 결과가 `날짜 없음`이 아닌 날짜별로 묶인다(`/api/journal/entries` 응답의 `stdrdDt`, §4.4.1·§4.4.2).
- [ ] **스택 화면에서 오늘 탭으로 복귀**: 태그별 기록 → (상세 → 다른 태그 → …) 처럼 쌓인 상태에서 날짜 헤더를 누르면 쌓인 화면이 닫히고 오늘 탭 일 모드로 그 날짜가 열린다. 뒤로 가기로 태그 화면이 다시 나오지 않는다(§4).
- [ ] **클립보드와 공유 시트**: 상세·이 날·이 주·이 달의 `복사` 후 다른 앱에 붙여 넣은 텍스트가 웹 복사 결과와 같다(날짜 줄·`#순번`·해석·빈 줄). `공유`가 시스템 공유 시트를 열고, 복사 성공 시 Android 토스트가 뜬다(§4.8).
- [ ] **스레드 글 목록**: 이 날/주/달의 스레드 칩, 엔트리 카드·상세의 `🧵` 칩을 누르면 `스레드 글 목록`이 오른쪽에서 열리고, 스레드 제목·말머리·라이프사이클·소속 기간·`소속 엔트리 N건`·본문·소속 엔트리 태그가 웹 스레드 상세와 같다. 글이 날짜별(최신순)로 묶이고 `오래된순`이 웹 순서와 같다. 글을 누르면 상세가 열려 본문·해석이 보이고, `스레드` 행에 그 엔트리의 모든 소속 스레드가 보인다(`entries/{id}/threads` 재조회). 날짜 헤더가 오늘 탭 그 날짜로 간다. 다른 사용자의 스레드 ID·삭제된 스레드는 오류 문구가 뜨고 앱이 멈추지 않는다(§4.9).
- [ ] **검색 태그 매칭**: 일기 필터로 태그 이름 일부를 검색하면 결과 위에 `일기 태그`·`일자 태그` 칩이, 꿈 필터로 바꾸면 `꿈 태그`만 나온다(일자 태그 없음). 9개 이상이면 `더보기`로 펼쳐진다. 칩을 누르면 맞는 종류의 태그별 기록이 열린다. 맞는 태그가 없으면 태그 영역이 보이지 않는다. 에뮬레이터에서 `dreamdiary`(일기 → 일기·일자 칩, 꿈 → 칩 없음)는 2026-10-06 확인, 실기기와 `더보기`·칩 이동은 미확인(§4.4.1).
- [ ] **검색 제출·초기화**: 검색어를 입력·수정하기만 해서는 결과·태그가 바뀌지 않고(요청 없음) `검색` 버튼·키보드 검색 키로만 검색된다. 제출 후 입력을 고친 채 필터를 바꾸면 마지막으로 제출한 검색어로 재검색된다. `✕`는 입력만 지우고, `초기화`는 입력·결과·태그를 비우되 필터는 유지한다(에뮬레이터에서 `✕`·`초기화` 표시와 꿈 필터 유지는 확인, §4.4.1).
- [ ] **결과 목록 복사**: 검색 결과·태그별 기록·스레드 글 목록의 `복사`가 머리줄(검색어·필터·건수 / 태그·연도·건수 / 스레드·기간·건수·정렬)과 화면 순서 그대로의 엔트리(날짜 줄·`유형 #순번 · 제목`·본문·해석)를 복사하고 건수 토스트가 뜬다. 결과가 없으면 바가 보이지 않는다(§4.8).
- [ ] **탭 바 선택 표시**: 선택한 탭 항목 전체에 둥근 배경이 깔리고 라벨이 강조색 굵은 글씨다. 비선택 탭 아이콘은 흐리고, 어떤 탭에서도 이모지 아이콘이 잘리거나 사라지지 않는다(§4).
- [ ] **햄버거 메뉴**: 오늘·검색·나 탭과 메뉴 화면 헤더의 `☰`을 누르면 왼쪽에서 드로어가 열리고, 웹 사이드바(사용자 모드)와 같은 묶음·이름·순서(`저널`: 저널 일자·저널 스레드·저널 결산 / `Keep` / `일반게시판`: 게시판들 / `일정`)가 보인다. 관리자 메뉴는 없다. 앱에 없는 메뉴(게시판·일정 달력)에 `준비 중` 배지가 있고 `Keep 전수관리`에는 없다. 현재 메뉴가 강조된다(오늘 탭 = 저널 일자, Keep 목록 = Keep 전수관리). 배경 탭·`✕`·뒤로 가기로 닫힌다(뒤로 가기는 드로어만 닫음). 웹에서 게시판을 추가하면 5분 안에(또는 앱 재시작 후) 드로어에 나타난다. 서버 메뉴 조회 실패 시 기본 메뉴와 안내 문구가 나온다. 노치·제스처 내비게이션 기기에서 패널 위아래가 잘리지 않는다. 에뮬레이터에서 열기·묶음·강조·뒤로 가기/배경 닫기·`저널 일자` → 오늘 탭은 2026-10-06 확인, 실패 폴백·iOS·실기기는 미확인(§4.10).
- [ ] **저널 스레드 목록**: `저널 스레드`가 목록을 열고 웹 스레드 목록과 순서·말머리·라이프사이클·소속 기간·건수가 같다. 끝까지 내리면 다음 페이지가 붙고(중복 없음), 제목 검색은 `검색`·키보드 검색 키로만 동작하며 `✕`로 전체 목록에 돌아온다. 스레드를 누르면 스레드 글 목록이 열린다. 에뮬레이터에서 첫 페이지(전체 60개) 표시는 확인, 페이지 이어 붙이기·검색은 미확인(§4.11).
- [ ] **저널 결산**: `저널 결산`이 연도별 카드와 `총 꿈 기록`을 웹과 같은 값으로 보여 주고, 카드를 누르면 결산 상세의 요약 본문·태그·리뷰가 웹과 같다(본문 HTML/마크다운이 텍스트로 읽히는지). 에뮬레이터에서 목록과 2026년 상세 표시는 확인(§4.12).
- [ ] **준비 중 화면**: 게시판·일정 달력이 `준비 중` 화면을 메뉴 이름과 함께 열고, 그 화면에서도 `☰`로 다른 메뉴로 갈 수 있다. 메뉴를 여러 번 오가도 뒤로 가기가 같은 화면을 반복하지 않는다(`pop: true`). 에뮬레이터에서 (당시 준비 중이던) Keep 전수관리로 확인(§4.13). Keep 전수관리는 이제 Keep 목록을 연다.
- [ ] **Keep 목록**: `Keep 전수관리`가 Keep 목록을 열고 전체 건수(2026-10-06 DB 기준 60건)가 `진행`·`종결` 합과 맞으며, 웹 `/keep`과 같은 항목·제목·말머리·태그·Project가 보인다. `진행` 순서가 웹(기한 오름차순, 기한 없음 아래)과 같고, `기한` 묶음(지남/오늘/7일 이내/그 이후)과 D-day가 기기 날짜 기준으로 맞다(자정 전후 포함). `종결` 배지 색(완료·실패·만료·내려놓음)이 구분된다. Project 칩(`전체`·`미지정`·OPEN Project)과 필터 시트(기한 지남·중요·말머리·태그)가 웹 필터와 같은 결과를 내고, 검색은 `검색`·키보드 검색 키로만 적용된다. 태그·말머리 선택지가 서버 응답으로 채워진다(실패 안내 문구가 없어야 함). 목록 복사·공유가 현재 보기·필터 결과를 §4.8 형식으로 담고, 당겨서 새로고침·웹에서 고친 뒤 화면 복귀 시 갱신된다. 체크박스·스와이프·`+`가 없다(§4.14).
- [ ] **Keep 상세**: 행을 누르면 상세가 열리고 라이프사이클(종결 항목은 종결 배지 — 상세 응답에 lifecycle이 없어 목록 값을 쓰는지)·중요/요구·기한·일시·위치·Project·말머리·태그·등록/수정·본문이 웹 상세와 같다. 마크다운 본문(목록·체크·링크)이 읽을 만한 평문으로 보인다. `복사`·`공유`가 동작하고 Android 토스트가 뜬다. 당겨서 새로고침 후에도 라이프사이클·Project 이름이 유지된다(§4.15).
